# authd の登録の形式

authd は、どの上流へ送ってよいかと、どのサロゲートをどの本物の鍵に差し替えてよいかを、1 つの YAML のファイル（登録）から読む。ADR-0003 の「本 ADR で決定しないこと」が委ねた、サロゲートの値の形と登録の形式をここで決める。

## 起動のしかた

authd は次の 3 つのフラグを取る。どれも必須で、欠ければ使い方の誤りとして終わる。

| フラグ | 中身 |
|---|---|
| `--config` | 登録のファイルのパス |
| `--socket` | 待ち受ける Unix socket のパス |
| `--peer-uid` | 関所の UID。この UID からの接続だけを受ける |

登録は起動のときに 1 度だけ読む。登録を変えたら authd を起動し直す。鍵のファイルの中身は別で、使うたびに読み直す（下の「鍵のファイル」）。

## 起動しないとき

次のどれかに当たれば、authd は socket を作らずに終わる。誤りの文は欄の名前と位置（`credentials[1]` など）で場所を示し、サロゲートと鍵の値は出さない。

- ファイルが読めない、空である、YAML として読めない。
- 知らない欄がある（綴りの誤りを見逃さないため）。
- 上流が 1 つも無い。上流の名前が無い、同じ名前が 2 度ある、名前にポートやパスが入っている、ポートが 1〜65535 の外。
- `ca_file` が読めない、証明書を 1 つも含まない。
- サロゲートが下の「サロゲートの値の形」に合わない、同じサロゲートが 2 度ある。
- `key_file` が無い、読めない、空である、制御文字を含む。
- 鍵の使い道の上流が空、または上流の一覧に無い名前を含む。置き場所が空、または置き場所の欄が下の表に合わない。

## 一番上の欄

| 欄 | 必須 | 中身 |
|---|---|---|
| `upstreams` | はい | 送ってよい上流の一覧。鍵の要らない上流（言語のパッケージの置き場など）もここに書く。ここに無い名前への要求は断る |
| `credentials` | いいえ | サロゲートと本物の鍵の組の一覧 |

## `upstreams` の 1 件

| 欄 | 必須 | 中身 |
|---|---|---|
| `name` | はい | 上流の名前。関所が判定に使い、authd がつなぐときに引き、証明書を確かめる名前。ホスト名か IP アドレスで、ポートは含めない。大文字と小文字は区別しない |
| `ports` | いいえ | 送ってよいポートの一覧。省けば 443 だけ |
| `ca_file` | いいえ | 上流の証明書を確かめる CA の PEM のファイル。省けば image の root 証明書で確かめる。クラスタの API のように自前の CA を持つ上流に使う |

authd は、名前とポートの組で上流を引く。登録の無い名前、登録の無いポートへの要求は、サロゲートの有無にかかわらず断る。

## `credentials` の 1 件

| 欄 | 必須 | 中身 |
|---|---|---|
| `surrogate` | はい | 道具に持たせるサロゲート |
| `key_file` | はい | 本物の鍵が入ったファイルのパス。mount した Secret のファイルや、kubelet が作り直す projected の ServiceAccount の token を指す |
| `upstreams` | はい | このサロゲートを差し替えてよい上流の名前の一覧。`upstreams` の一覧にある名前だけを書ける |
| `places` | はい | このサロゲートが置かれてよい場所の一覧（下の表） |

## 置き場所（`places` の 1 件）

| `type` | ほかの欄 | 探すところ | 差し替えたあと |
|---|---|---|---|
| `bearer` | `scheme`（省けば `Bearer`） | `Authorization` の値のうち、その scheme で始まるもの。scheme の大文字と小文字は区別しない | 同じ scheme のあとに本物の鍵 |
| `basic` | なし | `Authorization` の Basic のパスワード | 同じユーザー名と、パスワードに本物の鍵 |
| `header` | `name`（必須） | その名前のヘッダの値の全体 | 値の全体が本物の鍵 |
| `query` | `name`（必須） | その名前の query の引数の値の全体 | その引数の値だけが本物の鍵。ほかの引数と並びは元のまま |

- `scheme` を `token` にすれば、`Authorization: token …` の形で送る道具にも使える。
- `header` の `name` に `Authorization` は書けない。`bearer` か `basic` を使う。
- 値はサロゲートと全体で一致したときだけ差し替える。サロゲートを含むだけの値は差し替えない。

## 差し替えの決まり

authd は、登録したすべての置き場所を、すべての要求で探す。見つけたサロゲートごとに、次の順で確かめる。

1. そのサロゲートの `upstreams` に、要求の上流の名前があるか。無ければ断る（`surrogate-mismatch`）。
2. そのサロゲートの `places` に、見つけた置き場所があるか。無ければ断る（`surrogate-mismatch`）。
3. `key_file` が読めるか。読めなければ断る（`credential-unavailable`）。

すべて通れば、本物の鍵に差し替える。差し替えたあとのヘッダと query に、まだどれかのサロゲートが残っていれば（登録していない置き場所にあった、値の一部に含まれていた、など）、その要求も断る（`surrogate-mismatch`）。サロゲートのまま上流に送ることはしない。

要求の本文は探さない。本文にサロゲートを書いても本物にはならず、本文はそのまま送る。

サロゲートの無い要求は、鍵を付けずにそのまま送る。サロゲートでない `Authorization` の値も、そのまま送る。

## 鍵のファイル

- 鍵のファイルは、差し替えのたびに読み直す。ファイルが置き換わったら（kubelet が Secret を更新した、projected の token を作り直した）、次の要求から新しい鍵を使う。
- ファイルの前後の空白と改行は鍵に含めない。
- 読めない、空、制御文字を含むときは、その鍵を使う要求を断る。サロゲートの無い要求や、ほかの鍵を使う要求は止めない。

## サロゲートの値の形

- 16 文字以上の、空白を含まない表示できる ASCII 文字の並び。
- 秘密ではない（ADR-0003）。ただし、偶然ほかの値に紛れないよう、十分に長くて決まった前置きを持つ値にする。勧める形は、`surrogate-` のあとに、上流の名前と使い道の短い印と、乱数の 16 進を 32 文字ほど続けたもの。
- 登録の中で重ねない。

## 例として読む登録の形

ここでは文で示す。名前は架空のものである。

- 上流は 3 つ: `api.example.com`（ポート省略で 443）、`cluster.example.com`（ポート 6443、`ca_file` にクラスタの CA）、`packages.example.com`（鍵の要らない置き場、ポート省略）。
- 鍵は 2 つ:
  - 1 つ目のサロゲートは、`/var/run/secrets/authd/api-token` を鍵とし、`api.example.com` にだけ使える。置き場所は scheme `token` の `bearer` と `basic` の 2 つ（API の道具と git の両方で使うため）。
  - 2 つ目のサロゲートは、projected の ServiceAccount の token のファイルを鍵とし、`cluster.example.com` にだけ使える。置き場所は `bearer`。
