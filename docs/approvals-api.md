# 承認の口

関所が台帳（承認待ちと許し）に開く 2 つの口の、パス・欄・形式を決める。口を置くことと、それぞれにできることは ADR-0004（「ask はすぐ 403 で返し、答えは会話の外から届ける」「先に頼めるのは、具体的な操作と対象の一覧だけ」「運用の係は、自分の状態を読むだけ」）と ADR-0001（「承認を決められるのは本人だけで、会話の外で取る」）が決め、形をこの文書に委ねている。本人の側の画面と窓口は natsumi の ADR 0096 が決め、この文書の形を使う。

| 口 | 相手 | つなぎ方 | できること |
|---|---|---|---|
| 承認を受け付ける口 | natsumi の server | Unix socket（`-approvals-socket`）。`SO_PEERCRED` で `-approvals-peer-uid` の UID だけを受ける | 承認待ちを読む・答える、許しを読む・取り消す、出来事の流れ、記録を読む |
| 作業環境向けの口 | 作業環境 | 関所の固定の名前（`-gate-name`）の平文の HTTP（ポート 80） | 自分の承認待ち・許し・最近断られたものを読む、先に承認を頼む |

- どちらも HTTP/1.1 で、要求と答えの本文は JSON（`application/json`）である。知らない欄のある要求の本文は断る。
- 失敗の答えは、状態と `{"error": "<文>"}` である。文に鍵・token・サロゲートの値は入らない。
- 作業環境向けの口には、答える道も取り消す道も無い。答えのパスに要求しても 404 である。
- 部品の間に共有の秘密は置かない（ADR-0001）。承認を受け付ける口の相手は UID で分け、作業環境向けの口の相手は、要求が届いた向け直し元の待ち受けで分ける。

## 言葉と形

### 承認待ち

| 欄 | 中身 |
|---|---|
| `id` | 承認待ちの id（`ap-` で始まる） |
| `kind` | `request`（ask になった要求）か `beforehand`（作業環境が先に頼んだ一覧） |
| `state` | `open`（答えを待つ）・`allowed`・`denied`・`expired`（答えの無いまま時間が過ぎた） |
| `source` | 向け直し元の待ち受けの名前（`-source` の `name`） |
| `created`・`expires` | 作った時刻と、答えを待つ期限（RFC 3339、UTC） |
| `summary` | 関所が事実から組んだ 1 文。作業環境が書いた文は入らない |
| `items` | 中身の並び（下）。`request` は要求の操作ごとに 1 つ（ふつうは 1 つ。git の push は、許しの無い ref ごとに 1 つ） |
| `choices` | 出せる範囲の選択肢の並び（下）。画面はこれを並べるだけでよい |
| `requests` | 同じ要求が、この承認待ちに何度当たったか |
| `answered` | 答えた時刻（答えたときだけ） |
| `choice` | 許したときに選ばれた選択肢の `id` |
| `grants` | 許して台帳に入った許しの id の並び |

中身（`items` の 1 つ）:

| 欄 | 中身 |
|---|---|
| `destination` | 宛先の名前 |
| `method`・`path`・`query` | 要求の method・path・query（`request` だけ） |
| `operation` | 操作の名前。生の操作では無い |
| `params` | 操作の引数の並び。1 つずつ `{"name", "value"}` |
| `target` | 対象にする引数の名前の並び |
| `targetText` | 対象を `名前=値` を空白で区切って並べたもの |
| `facts` | コネクタが上流に引いた事実の並び（head の SHA、tag の commit が default の branch にあるか、push の変え方など）。1 つずつ `{"name", "value"}`。画面に出すだけで、照合には使わない（[GitHub のコネクタ](github.md)） |
| `body` | 要求の本文（[記録](audit.md) の「要求の本文」と同じ形。読みの要求と本文の無い要求には無い） |
| `fingerprint` | 1 回の許しで照合する指紋（下の「1 回の許しの照合」） |
| `exact` | 指紋が要求の全体を覆っているか |

- `params`・`body`・`path` などは、外の人が書いた文（PR の題や本文など）を含みうる。画面は平文として出し、HTML・Markdown・リンクとして解かない（natsumi の ADR 0096）。

選択肢（`choices` の 1 つ）:

| 欄 | 中身 |
|---|---|
| `id` | 答えで選ぶ値。`once`、または長さ（`1h`・`1d`・`30d`）か `forever` |
| `scope` | `once`（1 回）か `timed`（期限付き） |
| `seconds` | `timed` では許しの長さ（0 は期限なし）。`once` では、許しが使われるのを待つ長さ |
| `label` | 関所が組んだ、その範囲を言い表す文 |

- 選択肢は承認待ちを作ったときの振り分けの `approvals`（[振り分けの形式](routes.md)）から作り、その承認待ちの中では変わらない。
- `request` の承認待ちには、`once`（要求の全体を指紋で覆えたときだけ）と、`durations` の並びの順の `timed` を出す。`beforehand` には `once` だけを出す（ADR-0004 の「1 回の許しの束」）。
- `items` が複数の `request` の承認待ちでは、どの選択肢も、中身ごとに 1 つの許しを出す。`once` はすべての中身の指紋が要求を覆えたときだけ出す。

### 許し

| 欄 | 中身 |
|---|---|
| `id` | 許しの id（`gr-` で始まる） |
| `approval` | 許しを出した承認待ちの id |
| `source` | 許しが効く向け直し元 |
| `scope` | `once` か `timed` |
| `created`・`expires` | 作った時刻と期限。期限の無い許しには `expires` が無い |
| `summary` | 関所が組んだ、許しの範囲を言い表す文 |
| `destination`・`operation`・`target` | 許しが効く宛先・操作・対象 |
| `method`・`path` | 生の操作の期限付きの許しと、要求の 1 回の許しでは、その method と path |

## 範囲と照合

許しは、出した承認待ちと同じ向け直し元（`source`）の要求にだけ効く。表が `deny` の操作には、許しがあっても効かない（ADR-0004）。

| 範囲 | 効く要求 | 消えるとき |
|---|---|---|
| `request` の 1 回 | 指紋が同じ要求 1 つ | 使ったとき、`once` の長さが過ぎたとき、取り消したとき |
| `beforehand` の 1 回 | 同じ宛先の、同じ操作で、引数がすべて同じ要求 1 つ | 同上 |
| 操作の期限付き | 同じ宛先の、同じ操作で、対象が同じ要求 | 期限が来たとき、取り消したとき |
| 生の操作の期限付き | 同じ宛先に、同じ method と path で来た要求 | 同上 |

### 1 回の許しの照合

- 指紋は、向け直し元・宛先の名前・ポート・method・path・query と、関所が読んだ本文の SHA-256 である。git の push の ref は、本文の代わりにその ref の命令の行で指紋を作るので、pack の大きさにかかわらず `once` を出せる（[GitHub のコネクタ](github.md)）。
- 複数の中身の承認待ちから出た 1 回の許しは、要求の全体が通るときにだけ使われる。一部の中身にだけ許しがあって要求が通らないときは、その許しは使われずに残る。
- 関所が読む本文は、記録の本文の上限（振り分けの `bodyLimitBytes`、読みの要求では 0）までである。本文がその上限より長い要求は、指紋が全体を覆わないので、`once` の選択肢を出さない。期限付きだけを出す。
- 同じ指紋の要求が、答えの無い承認待ちに当たれば、新しく作らずにその承認待ちを返す（`requests` が増える）。答えが出た後に同じ要求が来て許しが無ければ、新しい承認待ちになる。

### 承認待ちの寿命

- 承認待ちは、振り分けの `approvals` の `pending`（既定は 1 日）のあいだ答えを待つ。過ぎたら `expired` で閉じる。閉じたものには答えられない。
- 関所は 1 分ごとに、期限の過ぎた承認待ちを閉じ、期限の来た許しを消す。答えの時に期限が過ぎていれば、そのときに閉じる。
- 閉じた承認待ちは台帳に残る。消す仕組みはこの版には無い。

## 承認を受け付ける口

| method とパス | すること | 答え |
|---|---|---|
| `GET /v1/approvals` | 承認待ちの一覧 | `{"approvals": [...]}` |
| `GET /v1/approvals/{id}` | 承認待ち 1 つ | 承認待ち |
| `POST /v1/approvals/{id}/answer` | 答える | 答えた後の承認待ち |
| `GET /v1/grants` | 効いている許しの一覧（古い順） | `{"grants": [...]}` |
| `DELETE /v1/grants/{id}` | 許しを取り消す | `{"revoked": 許し}` |
| `GET /v1/events` | 出来事の流れ | 1 行に 1 つの JSON（下） |
| `GET /v1/records` | 記録の一覧（新しい順） | `{"records": [...], "next": <id>}` |
| `GET /v1/records/{id}` | 記録 1 件 | 記録 |

### 一覧

- `GET /v1/approvals` の query: `state`（`open`・`allowed`・`denied`・`expired`・`all`。既定は `open`）、`source`、`limit`（既定 100、1000 まで）。`open` は古い順、ほかは新しい順である。

### 答え

要求の本文:

| 欄 | 中身 |
|---|---|
| `answer` | `allow` か `deny` |
| `choice` | `allow` のとき、承認待ちの `choices` の `id` の 1 つ。`deny` では書かない |

| 状態 | とき |
|---|---|
| 200 | 答えを受けた |
| 400 | 本文が読めない、`answer` が違う、`allow` に `choice` が無い、承認待ちが出していない `choice` |
| 404 | 承認待ちが無い |
| 409 | 承認待ちがもう閉じている（答えた後、期限の後）。同じ承認待ちには 1 度しか答えられない |
| 503 | 台帳か記録が使えない。答えは受けていない |

- 答えは、記録に書けてから台帳に効く。記録が書けなければ答えを受けない（ADR-0006）。
- `deny` は、その承認待ちだけを閉じる。表は変わらない。
- 取り消し（`DELETE /v1/grants/{id}`）も同じで、記録に書けてから消す。効いていない許しは 404 である。取り消しは出来事の流れに出さない（natsumi の ADR 0096）。

### 出来事の流れ

`GET /v1/events` は、閉じるまで続く答えである（`application/x-ndjson`）。1 行に 1 つの JSON を書く。

| `type` | 中身 |
|---|---|
| `hello` | つながった最初の 1 行 |
| `approval.created` | 承認待ちができた。`approval` に承認待ち |
| `approval.closed` | 承認待ちが閉じた（許した・断った・期限）。`approval` に閉じた後の承認待ち |
| `ping` | 30 秒ごと。つながっていることを確かめるため |

- 流れは、つながっているあいだの出来事だけを流す。切れていたあいだのものは残さない。つながり直したら `GET /v1/approvals` で一覧を読み、知らせ済みでないものを知らせる（natsumi の ADR 0096）。
- 読むのが遅れて溜まりすぎた出来事は落とす。落ちたものも一覧で拾える。
- 同じ要求が答えの無い承認待ちに当たっても、出来事は出さない。

### 記録を読む

- `GET /v1/records` の query: `kind`、`source`、`verdict`（何度でも書ける）、`before`（この id より前）、`limit`（既定 100、1000 まで）。
- 次の頁があれば `next` に、次に `before` に渡す id が入る。無ければ `next` は無い。
- 記録の欄は [関所の記録](audit.md) のとおりである。読むだけで、消す口も直す口も無い。

## 作業環境向けの口

| method とパス | すること | 答え |
|---|---|---|
| `GET /v1/status` | 自分の状態 | 下 |
| `GET /v1/approvals/{id}` | 自分の承認待ち 1 つ | 承認待ち（ほかの向け直し元のものは 404） |
| `POST /v1/approvals` | 先に承認を頼む | 201 と承認待ち |

- この口は、作業環境の通信が `-gate-address` のポート 80 に向かったとき（名前解決で `-gate-name` を引いた先）に開く。`-gate-name` を渡さなければ開かない。
- 読むだけの要求は記録しない。先に頼む要求は、記録（kind が `agent`）に書けてから承認待ちを作る。

### 自分の状態

| 欄 | 中身 |
|---|---|
| `approvals` | 答えを待つ自分の承認待ち（古い順） |
| `grants` | 自分に効いている許し |
| `refused` | 最近 1 日の、自分の要求のうち断られたもの（`deny`）と承認待ちにされたもの（`ask`）。新しい順に 20 件まで |

`refused` の 1 つは `time`・`verdict`・`name`・`method`・`path`・`operation`・`target`・`approval`・`reason` を持つ。本文と query は出さない。

### 先に承認を頼む

要求の本文は `{"items": [...]}` だけである。範囲の欄は無く、書けば断る（ADR-0004 の「範囲は運用の係が指定できない」）。`items` の 1 つ:

| 欄 | 中身 |
|---|---|
| `destination` | 宛先の名前（開く宛先） |
| `operation` | 操作の名前。宛先の規則のどれかが名付けている操作 |
| `params` | 引数の名前から値への対応。その操作を名付けた最初の規則の `path` と `body` の引数を、ちょうどすべて、空でない値で |

| 状態 | とき |
|---|---|
| 201 | 承認待ちを作った |
| 400 | 本文が読めない、`items` が 0 か 50 より多い、開く宛先でない、規則に無い操作、引数の過不足、表が allow の操作（頼むことが無い） |
| 403 | 表が deny の操作。承認では通せない |
| 503 | 台帳か記録が使えない。承認待ちは作っていない |

- 一覧は 1 つの承認待ち（`kind` が `beforehand`）になり、出せる範囲は `once` だけである。許せば、中身ごとに 1 回の許しが台帳に入る。
- 1 回の許しは、同じ宛先・同じ操作で、引数がすべて同じ要求に当たる。引数は並びの順を問わない。GitHub の宛先では、`owner` と `repo` を小文字に揃えて比べる。
- GitHub のマージは、マージの規則の `body` に `sha` を取らせておけば（[GitHub のコネクタ](github.md)）、`owner`・`repo`・`number`・`sha` で頼める。PR ごとに中身を 1 つにして、マージする PR の一覧を 1 つの承認待ちにする。REST のマージも GraphQL のマージ（`mergePullRequest`）も、同じ操作の名前と引数になるので、どちらの要求にも当たる。head が動いて SHA が変われば当たらない。
- 承認の画面に出す文（`summary`・`label`）は関所が組む。作業環境が理由を書く欄は無い。
- 生の操作は先に頼めない。名前の無い要求は、要求を出して ask になったものに答える。

## 宛先の許し

ADR-0007 で足すもので、まだ実装していない。台帳の中身と照合の決まりは [宛先の許し](destination-grants.md) にある。**ここに書くものは、今ある欄と口に足すだけで、今ある欄の意味と口の形は変えない。** 今の natsumi の承認の画面は、足した欄を知らなくても、今までどおり動く。

### 今ある形に足す欄

| 形 | 足す欄 | 中身 |
|---|---|---|
| 承認待ち | `kind` の値 `destination` | 運用の係が先に頼んだ宛先の一覧。中身（`items`）は `destination` と `facts` だけを持つ |
| 承認待ち | `options` | `kind` が `destination` のときだけ。期限のほかに選べる範囲（単位・扱い・読み書き）。形は [宛先の許し](destination-grants.md) の「選択肢の示し方」 |
| 許し | `kind` | `operation`（今ある許し）か `destination`（宛先の許し）。今ある許しにも付ける |
| 許し | `name`・`unit`・`handling`・`access` | `kind` が `destination` のときだけ。[宛先の許し](destination-grants.md) の「台帳に足すもの」 |
| 答えの要求の本文 | `options` | `kind` が `destination` の承認待ちに許すときだけ書ける。`{"unit", "handling", "access"}` で、どれも省ける（省けば既定）。ほかの承認待ちに書けば 400 |
| 自分の状態 | `refusedNames` | 最近 1 日に、自分の名前解決で断られた表に無い名前。新しい順に 20 件まで。1 つずつ `name`・`last`・`count` |

- `kind` が `destination` の承認待ちの `choices` は、`durations` の順の `timed` だけで、`once` は無い。
- 宛先の許しは `GET /v1/grants` の一覧に入り、`DELETE /v1/grants/{id}` で取り消せる。id は今の許しと同じ `gr-` の形である。
- 宛先の許しの `destination`・`operation`・`target`・`method`・`path` は無い。`summary` に範囲を言い表す文が入る。

### 承認を受け付ける口に足す口

| method とパス | すること | 答え |
|---|---|---|
| `GET /v1/refused-names` | 断った名前の一覧（`last` の新しい順） | `{"names": [...]}` |
| `POST /v1/refused-names/grant` | 断った名前の一覧から、宛先の許しを出す | 201 と `{"grant": 許し}` |

`GET /v1/refused-names` の query: `source`、`limit`（既定 100、1000 まで）。1 件は次の形である。

| 欄 | 中身 |
|---|---|
| `source` | 向け直し元 |
| `name` | 断った名前 |
| `first`・`last`・`count` | 最初と最後に断った時刻、回数 |
| `summary` | 関所が事実から組んだ 1 文 |
| `choices` | 期限の選択肢。承認待ちの `choices` と同じ形（`timed` だけ） |
| `options` | 単位・扱い・読み書きの選択肢。承認待ちの `options` と同じ形 |

`POST /v1/refused-names/grant` の要求の本文:

| 欄 | 中身 |
|---|---|
| `source` | 向け直し元 |
| `name` | 一覧にある名前 |
| `choice` | その名前の `choices` の `id` の 1 つ |
| `options` | 省ける。答えの `options` と同じ |

| 状態 | とき |
|---|---|
| 201 | 許しを出した |
| 400 | 本文が読めない、出していない `choice` や `options`、許されない名前（[宛先の許し](destination-grants.md) の「許されない名前」） |
| 404 | その向け直し元の一覧に名前が無い |
| 503 | 台帳か記録が使えない。許しは出していない |

- 許しは、記録（`kind` が `answer`）に書けてから台帳に効く。本人の答えとして 1 件ずつ知らせる（[知らせ](notices.md)）。
- 選択肢は、一覧を返したときの振り分けの `approvals` で作る。一覧を読んでから許すまでに振り分けが変われば、出していない `choice` として 400 になりうる。そのときは一覧を読み直す。
- 一覧から許しを出しても、承認待ちは作らず、出来事の流れにも何も出さない。

### 作業環境向けの口に足すもの

`POST /v1/approvals` の `items` の 1 つに、`destination` だけを書いた形を足す（`operation` と `params` を書かない）。

- これは表に無い宛先を頼むもので、一覧は `kind` が `destination` の 1 つの承認待ちになる。
- 1 つの一覧に、操作の中身と宛先の中身を混ぜれば 400 である。
- 名前が [宛先の許し](destination-grants.md) の「許されない名前」に当たれば 400、振り分けで deny の名前なら 403（承認では通せない）、もう当たる宛先の許しがあれば 400（頼むことが無い）である。
- 範囲の欄（期限・単位・扱い・読み書き）は書けない。書けば 400 である。
- 新しい道具（ツール）は足さない。運用の係は、今ある「先に承認を頼む」ツールで、この形を使う。ツールの説明に、宛先の形を書き足すのは環境のリポジトリである。

## natsumi の ADR 0096 との対応

ADR 0096 が関所の側に委ねたもののうち、この文書で決めたこと:

- socket の上の要求・答え・出来事の形（この文書の全体）。
- 承認待ちの期限: 答えの無い承認待ちは `pending`（既定 1 日）で閉じ、`approval.closed`（`state` が `expired`）を流す。ADR 0096 の「関所が別の理由で閉じた」はこれに当たる。
- 答えの二重: 2 度目以降は 409 で断る。
- 出せる範囲の選択肢とその意味: `choices` の `id`・`scope`・`seconds`・`label`。画面は `label` を並べ、選ばれた `id` を `choice` に入れて返せばよい。
- `/sources/sentinel/approvals/<id>.json` に置く事実: `approval.closed` の `approval` に、id・操作と対象（`items`）・結果（`state`）・許したときの範囲（`choice` と `choices`）と許し（`grants`）がそろっている。許しの期限は `GET /v1/grants` で引ける。

ADR 0096 が決めておらず、この文書で決めたこと:

- 承認の画面に出す 1 件の中身は `summary` と `items`（要求の method・path・query・操作・引数・対象・本文の頭）である。差分や head の SHA などは、GitHub のコネクタ（ADR-0005）が引数に足す。
- 出来事の流れは、つながったときに `hello`、30 秒ごとに `ping` を流す。server は `ping` が途絶えたらつなぎ直せる。
- 記録の画面は `GET /v1/records` の頁送りで読む。
