# 0006. 出ていくものを関所の記録に残し、いつもと違うことを知らせる

- Date: 2026-11-09
- Updated: 2026-11-12（本人の答えに、表に無い宛先への許しを出したことを足した。ADR-0008）
- Updated: 2026-11-13（関所が直に送った要求の失敗と、authd が鍵を渡さなかったことの記録と指標、関所が実際につないだアドレスを足した。ADR-0007・ADR-0008）
- Status: Accepted

## Context

natsumi は、守りを「防ぐ」より「すぐ気づく」に寄せる（natsumi の ADR 0095）。関所（ADR-0001）は、鍵の要る操作を判定と記録に通し、床の外の操作は許したうえで記録する。気づくための材料は、何が出ていったかの記録と、いつもと違うことの知らせである。

今の運用の係（クラスタの運用を受け持つ natsumi のインスタンス）の出口には、次のものしかない。

- 中継のアクセスログは method・パス・状態・時間だけで、ヘッダと本文は出さない（natsumi の ADR 0085）。何を書いたか（PR の本文、コメント）は残らない。
- ログはコンテナの標準出力だけで、クラスタにはログを溜める仕組み（Loki など）が無い。
- クラスタには Prometheus と Alertmanager があり、Alertmanager から Slack へ知らせる経路がある。どれもクラスタの中で動く。
- 運用の係の Pod は、1 つの永続ボリュームを subPath で分けて、作業環境や server と使っている。空きは共有である。

通したものが数えられるだけでは、異常には気づけない。記録を本人が毎日読みに行かない限り、通した操作の中のいつもと違うものは誰の目にも触れない。
本人は、私事の流出と本人に代わる約束に引き続き気をつけたい。運用の係が外へ書いた本文は、後から読めなければならない。

## Decision

### 何を残すか

- 関所を通るものは、扱い（ADR-0002 の Decision「扱いは宛先ごとに 3 つ」）にかかわらずすべて 1 件ずつ記録する。名前解決の問い合わせも残す。
- 記録には、いつ・どの向け直し元から（ADR-0002 の Decision「作業環境の通信は、iptables で関所に向け直す（透過プロキシ）」の待ち受け）・どの宛先へ・どの扱いで・どの操作として・どう決めたか（allow・ask・deny・許しに当たった、とその理由）を残す。
- **出ていく書きの本文は残す。** GitHub のコメント・PR や issue の本文、GraphQL の変数、REST の書きの本文、Kubernetes の API への書きの本文。
  - 1 件の本文には大きさの上限を置く。超えた分と、文字でない本文（バイナリ）は、大きさとハッシュだけを残す。
  - git の push は、命令の並び（ref と古い SHA・新しい SHA）だけを残す。中身は GitHub にある。
- **入ってくる応答と、読みは欄だけ残す。** 応答は状態・大きさ・時間、読みは宛先・path・query・状態。応答の本文は残さない。query を残すのは、query に載せた持ち出しも後から見えるようにするためである。
- passthrough は、宛先・ポート・量・時間だけを残す（中身は見えない）。
- 関所自身の上流への問い合わせ（ADR-0005 の対象の引き直しなど）も、関所の問い合わせとして残す。
- authd が断ったもの（ADR-0003 の Decision「authd も自分で確かめ、断ったことは関所が記録する」）は、authd から返った理由とともに関所が残す。
  - 関所が直に送った要求（最初の版では宛先の許しの通信）が上流に届かなかったときは、関所が理由とともに残す。次の版から、authd が鍵を渡さなかったときも、authd から返った理由とともに関所が残す。authd は、鍵を渡したことも渡さなかったことも記録しない（2026-11-13、ADR-0007）。
- 関所が名前を引き直して上流へ直につないだときは、実際につないだアドレスを残す。引いたアドレスでつながずに断ったときは、引いたアドレスを残す（2026-11-13、ADR-0008）。作業環境に答えたアドレスや元の宛先と食い違っても、どこへ届いたかが分かるようにする。
- 本人の答え（承認待ちへの答えと、許しの取り消し）を受けたことも残す。断った名前の一覧から本人が宛先の許しを出したことも、本人の答えとして残す（2026-11-12、ADR-0008）。
- 本物の鍵は残さない（関所は本物の鍵を見ない）。要求のヘッダは、操作と判定に使った欄のほかは残さない。

### どこに、どれだけ残すか

- 正本は関所の SQLite に置く。台帳（ADR-0004 の Decision「台帳」）と同じく、関所にだけ mount する**専用の volume** に置く。作業環境とは空きを分け、作業環境がディスクを埋めても記録が書けなくならないようにする。
- 同じ記録を 1 行の JSON で標準出力にも出す。ログを溜める仕組みがクラスタに入ったら、そこへ集める。標準出力は写しで、正本ではない。
- 記録を残す期間は関所の設定で決め、読み直しで変えられる。最初は 90 日とする。関所が 1 日 1 回、期間より古いものを消す。
- backup は、動いている SQLite をそのまま写さず、整合したコピーで取る。backup のコピーに残る分だけ、消えるのは遅れる（backup の保持の期間の分）。
- 台帳の許しは記録と別に持ち、期限切れか取り消しで消える。記録の期間とは関係しない。
- 特定の記録を手で消す道は、最初の版には入れない。

### 記録が書けなければ、通さない

- 記録を書けないとき（SQLite に書けない、volume が一杯など）は、その要求を通さない。記録の無い通信を作らない。
- 記録を書けないことは、下の指標に出して知らせる。

### いつもと違うことを知らせる

最初の版には判定器が無い（ADR-0001 の Decision「Muse と違えるところ」）。その代わりに、判定器なしで決められる「いつもと違う」を知らせる。

- **初めて見る組を、1 件ずつ知らせる。** 組は次のものである。
  - 宛先（振り分けにあって、初めて通った名前）。
  - 操作 × 対象（初めて通った書きの操作と、その対象）。
  - passthrough の宛先とポート。
  - 断った名前解決の名前。
- **本人の答えを受けたことを、1 件ずつ知らせる。** 関所は server の答えを信じるので（ADR-0001 の Decision「承認を決められるのは本人だけで、会話の外で取る」）、server が偽った承認にも本人が気づけるようにする。
- **1 日 1 回、まとめを出す。** 書きの件数（宛先と操作ごと）、その日に新しく現れた組、ask と deny の件数と中身、受けた答え。
- 知らせとまとめは、Slack の専用のチャンネルに届ける。届ける道は、natsumi にも運用の係にも頼らない。運用の係や natsumi が乗っ取られても、知らせは本人に届く。
- 「初めて見る」の覚えは、関所の SQLite に記録と別に持つ。記録の期間で消えても、覚えは消えない。

### 指標を出し、止まったことに外から気づく

- 関所は Prometheus の指標を出す。少なくとも、要求の数（宛先・扱い・決め方ごと）、deny と ask の数、承認待ちの数、設定の読み直しの失敗、記録の書き込みの失敗、上流への失敗、知らせの送り損ないを出す。
- authd も、断った数と、鍵の作り直しの失敗を指標に出す。次の版からは、authd の断った数は、関所に鍵を渡さなかった数になる。上流への失敗は、関所が直に送ったものも、関所の指標に出す（2026-11-13、ADR-0007）。
- 次の知らせの規則は、関所を入れる条件として必ず置く。設定の読み直しの失敗、記録の書き込みの失敗、知らせの送り損ない。規則は Alertmanager に置き、上の専用のチャンネルに届ける。critical のものは、今の critical の経路にも流す。
- 関所と authd の指標が途絶えたことを知らせる dead man's switch は、**受け手をクラスタの外に置く**。クラスタの中の Alertmanager から外の死活の見張りに定期の合図を送り、途絶えたら外から本人に知らせる。クラスタごと取られて Prometheus や Alertmanager が止まっても、途絶えたことは届く。

### 誰が読めるか

- 本人は、natsumi の画面で記録を読む（出ていく書きの本文を含む）。画面は natsumi の ADR 0096 が決める。
- 運用の係は、自分の承認待ち・効いている許し・最近断られたものと理由だけを読める（ADR-0004 の Decision「運用の係は、自分の状態を読むだけ」）。記録の全体は読めず、書き換えも消すこともできない。

### 守る対象と、倒す向き

- 守るのは、出ていったものが本人の読める記録に残ることと、いつもと違うこと、関所と authd が止まったことに、本人が natsumi と運用の係の外の道で気づけることである。
- 記録が書けなければ通さない側に倒す。指標が途絶えれば、知らせる側に倒す。

### 本 ADR で決定しないこと

- 記録の欄の名前と形、SQLite の表の形、本文の大きさの上限の値（委譲先: 関所の実装の PR と関所の設定）。
- 「初めて見る」の組の細かな取り方（対象をどこまで細かく見るか）と、まとめの形（委譲先: 関所の実装の PR）。
- 指標の名前と label（委譲先: 関所の実装の PR）。
- 知らせを Slack に届ける道の作り（Alertmanager を通すか、ほかの送り口か）（委譲先: 関所の実装の PR と、環境のリポジトリの監視の設定。natsumi と運用の係を経ないことだけをここで決める）。
- 知らせの規則としきい値、Slack のチャンネル、外の死活の見張り（委譲先: 環境のリポジトリの監視の設定）。
- 関所の専用の volume と backup の取り方・保持の期間（委譲先: 環境のリポジトリの配置と backup の設定。整合したコピーで取ることだけをここで決める）。
- ログを溜める仕組みと、そこでの異常の規則、クラスタの API server の監査のログ（委譲先: クラスタの監査の作業単位）。
- 本人が記録を読む画面（委譲先: natsumi の ADR 0096）。

## Consequences

- 運用の係が外へ書いた本文が、決めた期間のあいだ本人の読める形で残る。私事が混ざっていないかを後から確かめられる。
- 判定器が無くても、初めての宛先・初めての書きの操作・断った名前解決・受けた答えが、その場で本人に届く。通したものの中のいつもと違うことに、記録を読みに行かずに気づける。
- 毎日のまとめで、知らせを見落としても 1 日のうちに拾える。
- 最初のうちは、何もかもが「初めて」なので知らせが多い。慣れた組が増えるにつれて減る。知らせが多すぎて読まれなくなれば、気づく仕組みとして働かない。
- 関所が止まったことや、クラスタごと取られたことに、クラスタの外から気づける。外の死活の見張りという部品が 1 つ増える。
- 記録が書けないと通信が止まる。専用の volume にしたので作業環境のディスクの使い方には左右されないが、記録の volume の空きの監視が、運用の係の動きに直に効く。
- 出ていく書きの本文を残すので、本文に混ざった私事や秘密も、記録の中に期間のあいだ（backup を含めるとそれより長く）残る。記録を読める本人の画面と、backup の置き場の扱いに気をつける必要がある。
- 本文の大きさに上限があるので、大きな書きの中身は全部は残らない。大きさとハッシュから、上流のものと照らすことになる。push の中身も GitHub で見る。
- 応答の本文は残さないので、何を読んだかの中身は後から分からない。読んだことと宛先と query が分かる。
- 手で消す道が無いので、誤って残った秘密は期限まで消えない。
- 標準出力の写しは、ログを溜める仕組みが入るまで、コンテナのログの寿命でしか残らない。

## Alternatives Considered

- **知らせを関所の死活と、deny・ask の数だけにする**: 新しい方針では Kubernetes の書きも GitHub の allow の操作も「通して記録する」。通ったものは数が増えるだけで、いつもと違うものに気づく道が無い。
- **応答の本文も残す**: 読みの量は書きよりずっと多く、SQLite と backup が膨らむ。入ってくる文の判定（次の版）で要るようになったら、そのときに決める。
- **書きの本文に上限を置かず、push の pack も残す**: 大きな書きが続くと記録の volume が埋まり、fail closed で出口が全部止まる。
- **記録を運用の係の Pod の共有の永続ボリュームに置く**: 作業環境がディスクを埋めると記録が書けなくなり、運用の係が自分で直せない形で止まる。
- **記録が書けなくても通す**: 記録の無い通信が生まれ、「気づく」の前提が崩れる。
- **知らせを natsumi の Web Push や運用の係の会話で届ける**: 運用の係や natsumi が乗っ取られた・止まったときに、知らせも止まる。
- **dead man's switch をクラスタの中の Alertmanager で評価する**: クラスタごと取られるか Prometheus が止まると、「途絶えた」という知らせも出ない。
- **正本をログの溜め場に置く**: クラスタにはまだ無い。関所の SQLite なら、関所と同じ寿命で持て、台帳と同じ backup に乗る。
