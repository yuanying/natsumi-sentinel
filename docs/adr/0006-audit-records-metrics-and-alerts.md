# 0006. 出ていくものを関所の記録に残し、指標と知らせで異常に気づく

- Date: 2026-11-09
- Status: Accepted

## Context

関所の守りは「防ぐ」より「自由にさせて、すぐ気づく」を主にする（ADR-0001）。気づくための材料は、何が出ていったかの記録と、いつもと違うことの知らせである。

今の運用の係（クラスタの運用を受け持つ natsumi のインスタンス）の出口には、次のものしかない。

- 中継のアクセスログは method・パス・状態・時間だけで、ヘッダと本文は出さない（natsumi の ADR 0085）。何を書いたか（PR の本文、コメント、外の係への頼みの文）は残らない。
- ログはコンテナの標準出力だけで、クラスタにはログを溜める仕組み（Loki など）が無い。
- クラスタには Prometheus と Alertmanager があり、Alertmanager から Slack へ知らせる経路がある。

本人は、私事の流出と本人に代わる約束に引き続き気をつけたい。運用の係が外へ書いた本文と、外の係に頼んだ文は、後から読めなければならない。

## Decision

### 何を残すか

- 関所を通るものは、扱い（ADR-0002）にかかわらずすべて 1 件ずつ記録する。名前解決の問い合わせも残す。
- 記録には、いつ・誰の UID から・どの宛先へ・どの扱いで・どの操作として・どう決めたか（allow・ask・deny・許しに当たった、とその理由）を残す。
- **出ていく書きの本文は全部残す。** 外の係への頼みの文、GitHub のコメント・PR や issue の本文、GraphQL の変数、REST の書きの本文、操作の引数。
- **入ってくる応答と、読みは欄だけ残す。** 応答は状態・大きさ・時間、読みは宛先・path・状態。応答の本文は残さない。
- passthrough は、宛先・ポート・量・時間だけを残す（中身は見えない）。
- 本物の鍵は残さない（関所は本物の鍵を見ない。ADR-0003）。要求のヘッダは、操作と判定に使った欄のほかは残さない。

### どこに、どれだけ残すか

- 正本は関所の SQLite に置く。台帳（ADR-0004）と同じく、Pod の永続ボリュームの関所だけが mount する場所に置く。
- 同じ記録を 1 行の JSON で標準出力にも出す。ログを溜める仕組みがクラスタに入ったら、そこへ集める。標準出力は写しで、正本ではない。
- 記録は 90 日残す。関所が 1 日 1 回、90 日より古いものを消す。期間は関所の設定で、読み直しで変えられる。
- backup は、動いている SQLite をそのまま写さず、整合したコピーで取る。backup のコピーに残る分だけ、消えるのは遅れる（backup の保持の期間の分）。
- 台帳の許しは記録と別に持ち、期限切れか取り消しで消える。記録の 90 日とは関係しない。
- 特定の記録を手で消す道は、最初の版には入れない。

### 記録が書けなければ、通さない

- 記録を書けないとき（SQLite に書けない、永続ボリュームが一杯など）は、その要求を通さない。記録の無い通信を作らない。
- 記録を書けないことは、下の指標に出して知らせる。

### 指標を出し、異常を知らせる

- 関所は Prometheus の指標を出す。少なくとも、要求の数（宛先・扱い・決め方ごと）、deny と ask の数、承認待ちの数、設定の読み直しの失敗、記録の書き込みの失敗、上流への失敗を出す。
- authd も、断った数（組が登録と違う、など）と、鍵の作り直しの失敗を指標に出す。
- 知らせの規則は Alertmanager に置き、今の Slack への経路に、この知らせ専用のチャンネルを足す。critical のものは、今の critical の経路にも流す。
- 知らせの道は、natsumi にも運用の係にも頼らない。運用の係が乗っ取られても、知らせは本人に届く。
- 関所と authd の指標が途絶えたことも知らせる（dead man's switch）。関所が止まった・消されたことに、記録の外から気づけるようにする。

### 誰が読めるか

- 本人は、natsumi の画面で記録を読む（出ていく書きの本文を含む）。画面は natsumi の ADR が決める。
- 運用の係は、自分の承認待ち・効いている許し・最近断られたものと理由だけを読める（ADR-0004）。記録の全体は読めず、書き換えも消すこともできない。

### 守る対象と、倒す向き

- 守るのは、出ていったものが本人の読める記録に残ることと、関所と authd が止まった・おかしいことに本人が気づけることである。
- 記録が書けなければ通さない側に倒す。指標が途絶えれば、知らせる側に倒す。

### 本 ADR で決定しないこと

- 記録の欄の名前と形、SQLite の表の形（委譲先: 関所の実装の PR）。
- 指標の名前と label（委譲先: 関所の実装の PR）。
- 知らせの規則としきい値、Slack のチャンネル（委譲先: 環境のリポジトリの監視の設定）。
- backup の取り方と保持の期間（委譲先: 環境のリポジトリの backup の設定。整合したコピーで取ることだけをここで決める）。
- ログを溜める仕組みと、そこでの異常の規則、クラスタの API server の監査のログ（委譲先: クラスタの監査の作業単位）。
- 本人が記録を読む画面（委譲先: natsumi の ADR、リポジトリ `yuanying/natsumi` の `docs/adr/`）。
- 毎朝のまとめのような、知らせ以外の届け方（委譲先: 要るようになったときの ADR）。

## Consequences

- 運用の係が外へ書いた本文と、外の係に頼んだ文が、90 日のあいだ本人の読める形で残る。私事が混ざっていないかを後から確かめられる。
- 関所が止まったことや、断られる数の急な増え方に、natsumi と運用の係の外の経路で気づける。
- 記録が書けないと通信が止まる。永続ボリュームの空きの監視が、運用の係の動きに直に効く。
- 出ていく書きの本文を全部残すので、本文に混ざった私事や秘密も、記録の中に 90 日（backup を含めるとそれより長く）残る。記録を読める本人の画面と、backup の置き場の扱いに気をつける必要がある。
- 応答の本文は残さないので、何を読んだかの中身は後から分からない。読んだことと宛先だけが分かる。
- 手で消す道が無いので、誤って残った秘密は期限まで消えない。
- 標準出力の写しは、ログを溜める仕組みが入るまで、コンテナのログの寿命でしか残らない。

## Alternatives Considered

- **応答の本文も残す**: 読みの量は書きよりずっと多く、SQLite と backup が膨らむ。入ってくる文の判定（次の版）で要るようになったら、そのときに決める。
- **書きの本文も欄だけにする（今の中継と同じ）**: 何を書いたかが残らず、私事の流出や本人に代わる約束に後から気づけない。
- **記録が書けなくても通す**: 記録の無い通信が生まれ、「気づく」の前提が崩れる。
- **知らせを natsumi の Web Push や運用の係の会話で届ける**: 運用の係や natsumi が乗っ取られた・止まったときに、知らせも止まる。
- **正本をログの溜め場に置く**: クラスタにはまだ無い。関所の SQLite なら、関所と同じ寿命で持て、台帳と同じ backup に乗る。
