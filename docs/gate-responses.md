# 関所の応答

関所が自分で返す応答と、それを上流の応答と見分ける印を決める。印を付けることは ADR-0004 の Decision「ask はすぐ 403 で返し、答えは会話の外から届ける」が決め、印の名前と形をこの文書に委ねている。作業環境の道具と natsumi の側は、この印で関所の応答を見分ける。

## 印

- 関所が自分で作った HTTP の応答には、ヘッダ `Natsumi-Sentinel` を付ける。
- 上流から返った応答に同じヘッダがあれば、関所が取り除いてから作業環境に返す。作業環境に届く応答に `Natsumi-Sentinel` があれば、それは関所が作ったものである。
- 値は応答の種類を表す。

| 値 | 意味 | 要求は上流へ |
|---|---|---|
| `deny` | 関所が断った | 送っていない |
| `ask` | 本人の答えを待つ承認待ちにした。許されたら、同じ要求をやり直せば通る | 送っていない |
| `error` | 関所の側の失敗で、送れなかった・送りきれなかった | 送っていないか、送ったが上流の答えが届いていない |

- `ask` の応答には、ヘッダ `Natsumi-Sentinel-Approval` に承認待ちの id も付ける。上流の応答に同じヘッダがあれば、これも関所が取り除く。
- 本文は `text/plain` の 1 行で、`natsumi-sentinel: ` に続けて理由を書く。道具が本文を見せるなら、理由はそのまま利用者に届く。
- 鍵・token・サロゲートの値は、本文にも印にも出さない。

## 関所が返す応答

| 場面 | 状態 | 印 |
|---|---|---|
| 表（操作の行、または宛先の `default`）が deny | 403 | `deny` |
| 表が ask で、当てはまる許しが台帳に無い | 403 | `ask` |
| コネクタが要求を、受ける形に読めなかった（GitHub の 2 つの mutation の文書、SHA の無いマージ、読めない push の命令など） | 403 | `deny` |
| 台帳が読めない・書けない、コネクタの上流への問い合わせが答えを得られなかった | 503 | `error` |
| Host の名前が SNI と違う、Host のポートが接続のポートと違う、Host が無い（HTTP/1.0） | 403 | `deny` |
| upgrade（WebSocket など）を求める要求 | 501 | `deny` |
| CONNECT | 405 | `deny` |
| 平文の HTTP（TLS でない接続で HTTP の要求が来た） | 403 | `deny` |
| 記録が書けない | 503 | `error` |
| 上流へ渡せなかった（authd の断りを含む） | 502 | `error` |
| 要求の本文を読めなかった | 400 | `error` |

- ask の本文には、承認待ちの id、操作の名前と対象（生の操作ならそうと）、「本人が許したら同じ要求をやり直す」こと、自分の承認待ちを読む口の URL（`-gate-name` を渡したとき、`http://<名前>/v1/status`）を書く。git のように本文を見せない道具では、その口で承認待ちを知る（[承認の口](approvals-api.md)）。
- 同じ要求をやり直したとき、答えの無い同じ承認待ちがあれば、新しく作らずにその id を返す。
- 振り分けで断ったときの本文には、それが振り分けで決まっていて、変えるには本人が振り分けを直すことを書く（ADR-0004 の Decision「決めていないものは本人に聞く」の「deny も表のデータである」）。
- コネクタが断ったときの本文には、`refused: ` に続けて、要求のどこが受ける形でないかを書く。表を直しても変わらないので、振り分けの案内は書かない（[GitHub のコネクタ](github.md)）。
- 上流へ渡せなかったときの本文には、authd が返した理由の名前と文を書く（[関所と authd の間の形](authd-protocol.md) の「断りと失敗の形」）。authd が自分の確かめで断ったときは「authd refused the request」、確かめを通ったが上流から答えが得られなかったときは「authd could not get an answer from the upstream」で始まる。authd につながらなかったときは「authd could not be reached」とだけ書く。

## HTTP の応答を返せない場面

次の場面では HTTP の応答を返せないので、接続を切る。どれも記録には残る（kind が `connection` の記録）。

| 場面 | 作業環境から見えること |
|---|---|
| 振り分けに無い名前、`deny` の名前、受けないポートへの TLS | TLS の handshake が失敗する |
| SNI の無い TLS | TLS の handshake が失敗する |
| 関所の CA を信用していない道具 | TLS の handshake が失敗する |
| TLS でも HTTP でもない接続、何も送らない接続（10 秒） | 接続が切れる |
| 元の宛先が分からない接続 | 接続が切れる |
| passthrough で、記録が書けない | 接続が切れる（相手にはつながない） |

## 名前解決

| 場面 | 答え |
|---|---|
| 振り分けで `open` の名前の A | 本物の IPv4 の答え（TTL 30 秒） |
| 振り分けで `open` の名前の AAAA（IPv6 を向け直している向け直し元） | 本物の IPv6 の答え（TTL 30 秒） |
| 振り分けで `open` の名前の AAAA（IPv6 を向け直していない向け直し元） | NOERROR、答えなし |
| 振り分けで `open` の名前の A・AAAA 以外 | NOERROR、答えなし |
| IPv6 を向け直していて、`open` の名前が問い合わせの型のアドレスを持たず、もう片方の型だけを持つ | NOERROR、答えなし |
| 関所の固定の名前（`-gate-name`）の A | `-gate-address` |
| 関所の固定の名前の AAAA | NOERROR、答えなし |
| それ以外の名前（振り分けで deny の名前、振り分けに無い名前、`-dns-search-suffix` の接尾辞を付けた名前を含む） | NXDOMAIN |
| `open` の名前が上流の DNS に無い（IPv6 を向け直していれば、A も AAAA も無い） | NXDOMAIN |
| 上流の DNS が答えない | SERVFAIL |
| 記録が書けない | SERVFAIL |

## この版で扱わないもの

- HTTP/2 は扱わない。TLS の ALPN では `http/1.1` だけを示す。
- HTTP/1.1 で Host の無い要求と、HTTP として読めない要求には、関所の中の HTTP の server が印の無い 400 を返す。1 つも要求を読めないまま閉じた接続は、記録に残る。同じ接続の 2 つめ以降の要求でこれが起きたときは、その要求の記録は残らない。
