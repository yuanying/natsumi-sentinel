# 向け直しと待ち受け

作業環境の通信を関所に向け直す形と、そのために環境の側（Pod の初期化のコンテナが張る規則）で要るものを決める。向け直すこと、IPv6 も向け直すこと、AAAA を答える場合は ADR-0002 が決め、待ち受けの引数と規則の細かさをこの文書（と実装）に委ねている。

## 関所の待ち受け

向け直す元ごとに、`-source` を 1 つ渡す。値は `キー=値` をカンマでつないだものである。

| キー | 要るか | 中身 |
|---|---|---|
| `name` | 要る | 向け直す元の名前。記録の `source` になる |
| `proxy` | 要る | IPv4 の tcp を受ける待ち受け（アドレスとポート） |
| `dns` | 要る | IPv4 の名前解決を受ける待ち受け。同じアドレスとポートで udp と tcp を受ける |
| `proxy6` | いいえ | IPv6 の tcp を受ける待ち受け。IPv6 のアドレスとポート（`[::1]:ポート` の形） |
| `dns6` | いいえ | IPv6 の名前解決を受ける待ち受け。udp と tcp を受ける |

- `proxy6` と `dns6` は一緒に渡す。片方だけ、または IPv6 でないアドレス（IPv4 を IPv6 に写したものを含む）は、使い方の誤りとして起動しない。
- `proxy6` と `dns6` を渡した向け直し元では、関所は IPv6 も向け直されているものとして扱う。名前解決では、振り分けで開く名前の AAAA に本物の IPv6 を答え、片方の型のアドレスしか無い名前のもう片方の問い合わせには、答えの無い NOERROR を返す（[関所が返す応答](gate-responses.md) の「名前解決」）。AAAA の答えは、IPv4 の `dns` の待ち受けで受けた問い合わせにも同じに返す。
- 渡さなければ、関所は前の版と同じに動く。AAAA には答えを返さず、IPv4 を持たない名前は NXDOMAIN になる。
- **IPv6 の向け直しの規則を張らないまま `proxy6` と `dns6` を渡さない。** 関所が本物の IPv6 を答えると、道具は関所を通らない IPv6 の宛先を試す。規則が IPv6 を落としていれば、その宛先には届かない。

## 環境の側で要る規則

規則は、今と同じく初期化のコンテナが Pod の network namespace に張り、常駐するコンテナは書き換えられない（ADR-0002）。IPv4 は iptables、IPv6 は ip6tables で、同じ形の規則を両方に張る。張れなければ初期化のコンテナは失敗し、Pod は起動しない。

### 作業環境の UID

| 表 | 規則 | IPv4 | IPv6 |
|---|---|---|---|
| nat の OUTPUT | 名前解決（udp と tcp の 53）を REDIRECT | `dns` のポートへ | `dns6` のポートへ |
| nat の OUTPUT | loopback の宛先を除く tcp すべてを REDIRECT | `proxy` のポートへ | `proxy6` のポートへ |
| filter の OUTPUT | 向け直した後の宛先だけを通す | loopback の `proxy`・`dns` のポート | `::1` の `proxy6`・`dns6` のポート |
| filter の OUTPUT | それ以外を落とす | すべて | すべて |

- REDIRECT は、Pod の中で作られた通信を loopback（IPv4 は `127.0.0.1`、IPv6 は `::1`）へ向ける。関所の `proxy6` と `dns6` は `::1`（か `::`）で待ち受ける。
- filter の表は、向け直した後の宛先を見る。作業環境の UID には、関所の待ち受けへの通信だけが残る。
- 作業環境の IPv6 をいま全部落としている規則は、上の 4 つに置き換える。IPv6 の向け直しを張らない間は、今のまま落とし、関所に `proxy6` と `dns6` を渡さない。
- 作業環境向けの口（`-gate-name` と `-gate-address`）は IPv4 だけである。IPv6 では開かない。

### 関所の UID

| 宛先 | IPv4 | IPv6 |
|---|---|---|
| authd の socket | Unix socket（IP の規則に関わらない） | 同じ |
| passthrough の宛先 | 振り分けの `passthrough` の IPv4 の範囲とポート | 振り分けの `passthrough` の IPv6 の範囲とポート |
| 名前を引くためのクラスタの DNS | クラスタの DNS のアドレスの udp と tcp の 53 | クラスタの DNS が IPv6 のアドレスを持つときだけ、同じに |
| 宛先の許しの上流（`-destination-grants` のときだけ） | tcp の 443。ループバックとリンクローカルは落とす | IPv6 の宛先に届かせるなら、同じに |
| それ以外 | 落とす | 落とす |

- passthrough は元の宛先にそのままつなぐので、関所の UID の規則も同じ範囲とポートを開ける。振り分けに IPv6 の範囲を足したら、ip6tables の規則にも足す。
- 宛先の許しの上流の行は、本人が許した表に無い宛先の通信を、関所が authd を通さずに直に送るためのものである（ADR-0007・ADR-0008、[宛先の許し](destination-grants.md) の「環境の側で変わるもの」）。宛先の許しを使わない環境では開けない。どの名前へつなぐかと、ループバックとリンクローカルにつながないことは、関所の中でも確かめる。クラスタの中と LAN の宛先は、この規則では落とさない。外の名前を私用の範囲につながないことは関所の中で確かめ、内側のドメインの一覧の名前がどこへ届いてよいかは、環境の側のネットワークの規則（NetworkPolicy など）で決める。
- 鍵付きの通信を関所へ移す次の版（ADR-0007）では、この表と下の authd の UID の表が変わる。変わる中身は、その版の実装の PR が決める。

### authd の UID

| 宛先 | IPv4 | IPv6 |
|---|---|---|
| 登録した上流のポート（省略は 443） | 開ける | IPv6 の宛先に届かせるなら開ける |
| 名前を引くためのクラスタの DNS | 開ける | クラスタの DNS が IPv6 のアドレスを持つときだけ |
| それ以外 | 落とす | 落とす |

- authd は登録の名前を引き直し、IPv4 でも IPv6 でもつなぐ（Go の既定の dial）。IPv6 の外向きを落としていると、IPv6 しか持たない上流にはつながらず、その要求は `upstream-unreachable` になる。
- 上流が IPv4 と IPv6 の両方を持つとき、片方の外向きを落としていても、もう片方でつながる。

### kernel

- ip6tables の nat の表（`ip6table_nat`、または nf_tables の IPv6 の nat）が要る。無い kernel では IPv6 の向け直しを張れない。関所の `make test-netns` の IPv6 のテストは、その場合 skip する。
- Pod の network namespace に IPv6 が無い（loopback に `::1` が無い）ときは、`proxy6` と `dns6` を待ち受けられず、関所は起動しない。
