# 振り分けの形式

関所（`sentinel`）が宛先ごとの扱いを決める設定（振り分け）と、開く宛先の要求を allow・ask・deny に決める表の形式を決める。扱いの意味は ADR-0002 の Decision「扱いは宛先ごとに 3 つ」、表の意味は ADR-0004 の Decision「宛先ごとの既定と規則で、allow・ask・deny を決める」、読み直しの決まりは ADR-0004 の Decision「設定は、Pod を作り直さずに読み直す」、記録の期間と本文の上限は ADR-0006 の Decision「どこに、どれだけ残すか」が決める。この文書は、それを書き表す形だけを決める。

## 置き場所と読み方

- 振り分けは 1 つのディレクトリに置き、`-config` でその場所を渡す。ConfigMap を、中身のハッシュを名前に付けずに mount することを想定している。
- ディレクトリの中の、名前が `.yaml` か `.yml` で終わるファイルをすべて読み、1 つの振り分けとして合わせる。読む順はファイルの名前の順である。
- 名前が `.` で始まるもの（ConfigMap の mount が置く `..data` など）と、ほかの拡張子のファイルは読まない。
- 振り分けのファイルが 1 つも無いディレクトリは、読めないものとして扱う。
- どのファイルも YAML の 1 つの文書で、一番上に置けるのは下の 4 つの欄だけである。知らない欄があれば、そのファイルは読めない。

| 一番上の欄 | 中身 | 省略したとき |
|---|---|---|
| `destinations` | 名前で決める宛先の並び | 名前で決める宛先は無い |
| `passthrough` | IP の範囲とポートで通す宛先の並び | passthrough は無い |
| `audit` | 記録の設定 | 既定の値 |
| `approvals` | 本人に聞くときの設定 | 既定の値 |

## destinations

宛先の名前ごとに 1 つ書く。

| 欄 | 中身 | 要るか |
|---|---|---|
| `name` | 宛先の名前（TLS の SNI と HTTP の Host に出るもの） | 要る |
| `treatment` | `open`（開く）か `deny`（通さない） | 要る |
| `default` | `allow`・`ask`・`deny`。規則に当たらない要求と、`operations` に行の無い操作の扱い | `open` のときは要る。`deny` のときは書けない |
| `ports` | その名前で受けるポートの並び | 省略すると 443 だけ |
| `rules` | 要求を操作に揃える規則の並び（下の「rules」） | 規則は無い。要求はすべて生の操作になる |
| `operations` | 操作の名前から `allow`・`ask`・`deny` への対応 | 行は無い。どの操作も `default` で決まる |

- 名前は大文字と小文字を区別せず、末尾の `.` を取って比べる。同じ名前を 2 度書くと（別のファイルでも）読めない。
- IP アドレスは名前に書けない。IP を直に書いた URL は SNI が無いので、開く宛先にはならない（ADR-0002 の Decision「名前で決め、名前を引き直してつなぐ」）。
- 振り分けに無い名前と、`ports` に無いポートへの接続は deny と同じに扱う。`treatment: deny` は、断っていることを振り分けの上で明らかにするために書く。
- 名前解決で本物の IP を答えるのは `open` の名前だけである。`deny` の名前と振り分けに無い名前には NXDOMAIN を答える。
- `rules` と `operations` は `open` の宛先にだけ書ける。

## rules

開く宛先の要求を、method と path から操作の名前に揃える（ADR-0004 の「操作」）。上から順に見て、最初に当たった規則で決まる。どの規則にも当たらない要求は **生の操作** で、名前を持たず、宛先・method・path で表される。

| 欄 | 中身 | 要るか |
|---|---|---|
| `operation` | 操作の名前。英数字・`.`・`_`・`-` で、英数字で始まる | 要る |
| `methods` | 当てる method の並び。大文字と小文字は区別しない | 省略するとどの method にも当たる |
| `path` | 当てる path の形（下） | 省略するとどの path にも当たる |
| `target` | 操作の対象にする引数の名前の並び。`path` の引数から選ぶ | 省略すると `path` の引数すべて |

- `path` は `/` で始め、`/` で区切った 1 つずつの区切りを比べる。`{名前}` は空でない 1 つの区切りに当たり、その値を引数にする。最後の区切りに限り `{名前...}` と書け、残りの path（`/` を含む、空でない）に当たる。ほかの区切りは文字どおりに比べる（大文字と小文字を区別する）。1 つの区切りの一部だけを引数にはできない。
- 比べるのは、query を除き、`%` の符号を解いた path である。末尾の `/` の有無も違う path として比べる。
- 引数のうち `target` に挙げたものが操作の **対象** で、期限付きの許しはこの対象で引く（ADR-0004 の「操作 × 対象」）。ほかの引数は 1 回の許しの照合にだけ使う。たとえば PR のマージで対象をリポジトリまでにすれば、期限付きの許しはそのリポジトリのマージすべてに効く。
- 記録と承認の画面では、対象を `名前=値` を空白で区切って、`path` に書いた順に並べて表す。
- 宛先に固有のコネクタ（ADR-0005 の GitHub など）は、この規則より先に要求を読み、操作と対象を決められる。コネクタを持つ宛先は、この版には無い。

## operations

操作の名前ごとに、`allow`・`ask`・`deny` を書く。

- 行の無い操作と生の操作は、宛先の `default` で決まる。
- `deny` は本人の許しより勝つ。期限付きの許しがあっても、表が後から `deny` に変われば断る（ADR-0004）。
- `allow` の操作は台帳を見ずに通す。`ask` の操作は、当てはまる許しが台帳にあれば通し、無ければ本人に聞く。

## approvals

振り分け全体で 1 度だけ書ける。長さは `30m`・`1h`・`30d` の形（`d` は日）で書く。

| 欄 | 中身 | 省略したとき |
|---|---|---|
| `durations` | 期限付きの許しの選択肢の並び。`forever` は期限なし。並べた順に承認の画面に出る。1 つ以上 | `1h`・`1d`・`30d`・`forever` |
| `once` | 1 回の許しが使われるのを待つ長さ。過ぎたら消える | `10m` |
| `pending` | 承認待ちが答えを待つ長さ。過ぎたら閉じる | `1d` |

- 選択肢と長さは、承認待ちを作ったときと本人が答えたときに読めている振り分けの値が効く。答えた後に `durations` を変えても、出した許しの期限は変わらない。

## passthrough

元の宛先の IP の範囲とポートの組ごとに 1 つ書く。

| 欄 | 中身 | 要るか |
|---|---|---|
| `cidr` | IP の範囲（`192.0.2.0/24` の形） | 要る |
| `ports` | 通すポートの並び。1 つ以上 | 要る |

- 元の宛先がどれかの範囲に入り、ポートがその組の `ports` にあれば、関所は中身を開かずに直につなぐ。名前は見ない。
- passthrough は名前で決める宛先より先に見る。範囲に入った接続は、TLS でも開かない。

## audit

振り分け全体で 1 度だけ書ける。2 つのファイルに書くと読めない。

| 欄 | 中身 | 省略したとき |
|---|---|---|
| `retentionDays` | 記録を残す日数。1 以上 | 90 |
| `bodyLimitBytes` | 書きの本文を記録に残す上限のバイト数。0 以上 | 65536 |

- 期間は、関所が起動したときと、その後 1 日に 1 度、消すときに読み直したものが効く。
- 上限は、そのときに読めている振り分けの値が、要求ごとに効く。

## 読み直し

- 関所は `-reload-interval`（既定 10 秒）ごとにディレクトリを見て、ファイルの名前か中身が変わっていれば読み直す。
- 読み直した振り分けが読めなければ、それを採らず、前に読めた振り分けのまま動く。そのことを記録に残し、標準エラーに出す。同じ中身のまま壊れていても、知らせるのは変わったときの 1 度だけである。
- ディレクトリそのものが読めないときは、見るたびに記録に残す。
- 新しい振り分けが効くのは、それより後に来た接続と問い合わせである。続いている接続は、始まったときの振り分けのまま動く。
- 起動のときに読めなければ、関所は起動しない。

## 確かめるだけの動かし方

`sentinel -check -config <ディレクトリ>` は、振り分け（表と `approvals` を含む）を読めるかだけを確かめて終わる。読めれば 0、読めなければ理由（どのファイルのどの欄か）を標準エラーに出して 1 で終わる。環境のリポジトリの CI で、振り分けの変更をマージする前に通すことを想定している（ADR-0004）。
