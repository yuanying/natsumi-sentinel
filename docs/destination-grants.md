# 宛先の許し

表に無い宛先（振り分けに名前の無い宛先）を、本人の許しで通すための仕様を決める。断った名前を覚えること、許しの単位・期限・扱い・読み書き、ポート、関所が鍵を付けずに直に送ること、判定の場所を 1 つにすることは ADR-0008（と、出口の形は ADR-0007）が決め、台帳・照合・名前解決・記録・知らせ・指標の形をこの文書（と実装）に委ねている。承認の口と作業環境向けの口に足すものは [承認の口](approvals-api.md) の「宛先の許し」にある。

**この文書は実装の前の下書きである。** 「実装の PR に委ねる」と書いたものは、実装の PR が決めて、この文書を直す。

## 言葉

| 言葉 | 意味 |
|---|---|
| 表に無い名前 | 振り分けの `destinations` に無い名前。`treatment: deny` の名前と、ほかのポートで書かれた名前は含まない（振り分けにある） |
| 断った名前 | 表に無い名前のうち、作業環境が名前解決で引き、関所が NXDOMAIN を返したもの |
| 宛先の許し | 表に無い名前に本人が出す許し。台帳の許しの 1 種類 |
| 操作の許し | 今ある許し（[承認の口](approvals-api.md) の「許し」）。宛先の許しと分けて呼ぶときに使う |

## 許されない名前

次の名前には、宛先の許しを出せない。承認の口も作業環境向けの口も 400 で断る。

- 振り分けにある名前（扱いとポートを問わない）。振り分けを直す。
- IP アドレス（IPv4 も IPv6 も）。
- 関所の固定の名前（`-gate-name`）。
- 振り分けにある名前に `-dns-search-suffix` の接尾辞を付けた名前。
- 公開の接尾辞そのもの（`com`、共有のドメインなど）。
- 名前として形の正しくないもの（ラベルが 63 バイトを超える、全体が 253 バイトを超える、使えない文字を含む）。

名前は振り分けと同じく、大文字と小文字を区別せず、末尾の `.` を取って比べる。

## 台帳に足すもの

### 宛先の許し

| 欄 | 中身 |
|---|---|
| `id` | 許しの id（`gr-` で始まる。操作の許しと同じ形で、同じ一覧と取り消しの口で扱えるようにする） |
| `kind` | `destination`。操作の許しは `operation`（[承認の口](approvals-api.md) で、今ある許しにも足す） |
| `approval` | 許しを出した承認待ちの id。断った名前の一覧から出したものには無い |
| `source` | 許しが効く向け直し元 |
| `name` | 許した名前。`unit` が `domain` のときはドメイン |
| `unit` | `name`（この名前だけ）か `domain`（このドメインの下すべて。ドメインそのものも含む） |
| `handling` | `inspect`（開いて見る）か `passthrough`（開かない） |
| `access` | `read`（読みだけ）か `readwrite`（読み書き）。`handling` が `passthrough` のときは無い |
| `created`・`expires` | 作った時刻と期限。期限の無い許しには `expires` が無い |
| `summary` | 関所が組んだ、許しの範囲を言い表す文 |

- 宛先の許しには `scope` の `once` は無い。いつも `timed` である（期限なしを含む）。
- 同じ向け直し元に、同じ名前を覆う許しが複数あってもよい。照合は下の「照合の決まり」のとおり、いちばん広いものではなく、当たったもののうち決まった順で 1 つを選ぶ。

### 断った名前の覚え

| 欄 | 中身 |
|---|---|
| `source` | 向け直し元 |
| `name` | 断った名前 |
| `first`・`last` | 最初と最後に断った時刻 |
| `count` | 断った回数（問い合わせの型を問わない） |
| `domain` | その名前の登録できるドメイン（公開の接尾辞のすぐ下。一覧のどの規則にも当たらない名前では、既定の規則で決めたもの） |

- 覚えるのは、表に無い名前の理由（`not an open destination in the routing table: the name is not in the table`、[関所の記録](audit.md)「名前解決の記録の理由」）で断った名前だけである。振り分けで deny の名前と、search の接尾辞を付けただけの名前は覚えない。上の「許されない名前」に当たるものも覚えない。
- 向け直し元と名前で 1 行である。同じ名前をまた断ったら、`last` と `count` だけを更新する。
- 宛先の許しを出した名前（許しに覆われた名前）は、一覧から外す。許しが切れてまた断られたら、新しく覚える。
- 上限: 向け直し元ごとに決まった数までを覚え、超えたら `last` の古いものから落とす。一定の日数より前に `last` のあるものも落とす。数と日数は実装の PR に委ねる（振り分けの設定にするかも含めて）。
- 覚えを書けなくても、名前解決の答え（NXDOMAIN）は変わらない。書けなかったことは指標に出す。覚えは記録の正本ではない（記録は今までどおり 1 件ずつ残る）。
- 覚えは、名前のほかに関所が上流から引いたものを持たない。表に無い名前は、許されるまで上流の DNS に問い合わせない。

## 承認待ちに足すもの

運用の係が先に頼んだ宛先は、1 つの承認待ちになる。

- `kind` は `destination`。
- `items` の 1 つは、`destination`（頼んだ名前）だけを持つ。`operation`・`params`・`target` などは無い。中身の事実として、`facts` に、その名前を断った回数と最後の時刻（覚えにあれば）、登録できるドメインを入れる。
- `choices` は、振り分けの `approvals` の `durations` の順の `timed` だけで、`once` は無い。
- 新しい欄 `options` に、本人が選べる残りの範囲を示す（下の「選択肢の示し方」）。
- 許せば、中身ごとに 1 つの宛先の許しが台帳に入り、その id が `grants` に入る。

## 選択肢の示し方

宛先の許しの範囲は、期限・単位・扱い・読み書きの 4 つを組み合わせる。組み合わせを `choices` に並べると数が多くなるので、期限だけを `choices` に、ほかの 3 つを `options` に分ける。`options` は承認待ち（`kind` が `destination`）と、断った名前の一覧の 1 件に付く。

| 欄 | 中身 |
|---|---|
| `unit` | 単位の選択肢の並び。1 つずつ `{"id", "label"}`。`id` は `name` か `domain:<ドメイン>`。最初のものが既定（`name`） |
| `handling` | 扱いの選択肢の並び。`id` は `inspect`（既定）か `passthrough` |
| `access` | 読み書きの選択肢の並び。`id` は `read`（既定）か `readwrite` |

- `unit` の `domain:` は、名前の親のうち、登録できるドメインまでのものを、近い順に並べる（`a.b.example.com` なら `domain:b.example.com`・`domain:example.com`）。名前そのものが登録できるドメインなら、`domain:<その名前>` だけを出す。名前が一覧のどの規則にも当たらないときは、一覧の既定の規則（最後の 1 ラベルを接尾辞とみなす）で決まる登録できるドメインまでを並べる（接尾辞の `example` が一覧に無いので、`a.b.c.example` なら `domain:b.c.example`・`domain:c.example`）。一覧は ICANN の部と私設の部の両方を使う。
- 承認待ちの `facts` と、断った名前の一覧の 1 件に、名前が内側の名前かどうかを入れる。画面はそれを内側の名前として示す。
- `label` は関所が組む。`domain:` の `label` は、そのドメインそのものとその下のすべての名前が通ることを言う。一覧の既定の規則で決めたドメインでは、接尾辞が一覧に無く、関所が上限を決めていないことも言う。許しの `summary` にも同じことを入れる。
- 答えに `options` を書かなければ、どれも最初のもの（既定）になる。今の natsumi の承認の画面は `choice` だけを送るので、そのままで「この名前だけ・開いて見る・読みだけ」の許しになる。
- `handling` に `passthrough` を選んだときは、`access` を書いても使わない。`passthrough` の `label` は、読み書きとも通り、中身を見ないことを言う文にする（「読み書きとも通る。中身は見ない」の類）。許しの `summary` にも同じことを入れる。

## 照合の決まり

### どの許しが当たるか

名前 `n`・向け直し元 `s`・ポート `p` の名前解決・接続・要求に、次をすべて満たす宛先の許しが当たる。

- `source` が `s`。
- 期限が来ていない。
- `unit` が `name` で `name` が `n`、または `unit` が `domain` で、`n` が `name` と同じか、`n` が `.` と `name` で終わる。
- `p` が 443。
- 名前が振り分けに無い（振り分けにあれば、許しを見ずに振り分けで決める）。

当たる許しが複数あれば、`handling` が `inspect` のものを先に、その中で `access` が `readwrite` のものを先に、さらに `unit` が `name` のものを先に、最後に古いものを選ぶ。開いて見る許しがあるのに passthrough で通る、ということを起こさないためである。

### 名前解決

| 場面 | 答え |
|---|---|
| 当たる宛先の許しがある名前の A | 上流の DNS で引いた本物の IPv4（TTL は振り分けの名前と同じ） |
| 当たる宛先の許しがある名前の AAAA | 振り分けの名前と同じ決まり（IPv6 を向け直している向け直し元だけ本物の IPv6） |
| 表に無い名前で、当たる許しが無い | NXDOMAIN。上流には問い合わせない。覚えに足す |
| 台帳が読めない | NXDOMAIN（許しが無いものとして扱う）。記録に失敗を残す |

- 記録の理由は、許しで答えた名前に「a destination grant covers the name」の類を付け、`grant` に許しの id を入れる（文は実装の PR が決める）。
- 名前解決で答えるのは、ポートを問わない（名前解決にポートは無い）。許しの無いポートへの接続は、接続のときに断る。

### 接続と要求

| ポート | 扱い | 関所がすること |
|---|---|---|
| 443 | `inspect` | 振り分けの開く宛先と同じに TLS を終端し、要求ごとに下の「読みと書き」で決め、通すものは関所が上流へ直に送る（下の「関所が直に送る」） |
| 443 | `passthrough` | TLS の ClientHello の SNI を読み（終端しない）、許しを引き、SNI の名前を引き直して、そのアドレスにつなぐ。SNI が無ければ断る |
| それ以外（80 を含む） | | 断る（今の「振り分けに無い名前」と同じ）。平文の HTTP は今までどおり 403 で断る |

- passthrough は、今の振り分けの `passthrough`（IP の範囲）より後に見る。元の宛先が振り分けの passthrough の範囲に入っていれば、今までどおり IP の範囲で通す。
- 宛先の許しの passthrough は、名前を引き直したアドレスにつなぐ。元の宛先の IP にはつながない。作業環境が名前と IP を食い違わせても、許した名前の本物の宛先にしか届かない。
- 引き直したアドレスがループバックかリンクローカルなら、つながずに断る。外の名前で私用の範囲のアドレスなら、つながずに断る（下の「関所が直に送る」と同じ範囲）。
- 続いている接続は、要求ごとに許しを引き直す（開いて見る宛先）。passthrough の接続は、つないだときの許しで最後まで続き、許しが切れても切らない。

### 読みと書き

宛先の許しで開いた要求は、規則を持たない仮の開く宛先として、今の判定（[振り分けの形式](routes.md) の `default` と、ADR-0004）に掛ける。

| `access` | 読みの要求 | 書きの要求 |
|---|---|---|
| `read` | allow | ask（生の操作として承認待ち） |
| `readwrite` | allow | allow |

- 読みは method が GET・HEAD・OPTIONS・TRACE のもの（[関所の記録](audit.md) の `read` と同じ）。
- 書きの承認待ちは、今の `request` の承認待ちと同じで、出せる範囲も同じ（1 回と、同じ宛先・method・path への期限付き）。許した操作の許しは、宛先の許しが切れた後には効かない（宛先の許しが無ければ、要求そのものが届かない）。
- 書きの本文は、振り分けの開く宛先と同じに記録に残す。
- GitHub のコネクタ（`github` の節）は、宛先の許しの宛先には使わない。GitHub の名前は振り分けにある。

## 関所が直に送る

宛先の許しの通信は、authd に渡さず、関所が上流へ直に送る（ADR-0007 の Decision「移す順番」、ADR-0008）。[関所と authd の間の形](authd-protocol.md) と [authd の登録の形式](authd-registration.md) には何も足さない。今の「`https` 以外の URL は authd に渡さない」もそのままである。

関所の上流へ送る部品は、今 authd が [関所と authd の間の形](authd-protocol.md) の「socket の上の形」でしていることを、同じに守る。

- 許しで決めた名前を引き直してつなぐ。元の宛先の IP にはつながない。
- 引いたアドレスのうち、ループバックとリンクローカル（メタデータの口を含む）のものには、どの名前でもつながない。
- 私用の範囲（LAN と、環境のクラスタの中の Service・Pod のアドレス）には、下の「内側のドメインの一覧」のドメインの下の名前だけをつなぐ。外の名前では、私用の範囲のアドレスにはつながない。
- つなげるアドレスが 1 つも無ければ断る。断った記録には、引いたアドレスを残す。
- 内側の名前が公のアドレスを指したときは、断らずにつなぎ、記録に印を付ける（下の「記録に足すもの」）。知らせは足さない。
- 一覧の名前がどの内側の宛先へ届いてよいかは、環境の側のネットワークの規則が受け持つ。
- 上流の証明書を、image の root 証明書と、その名前で確かめる。
- ポートは 443 だけで、HTTPS でしか送らない。
- 上流へは HTTP/1.1 で送る。リダイレクトはたどらない。応答は溜めずに流す。圧縮は足さず、外さない。中継のヘッダは足さない。
- 鍵は付けない。要求のヘッダか query に、authd の登録にあるサロゲートが（値の全体でも一部でも）載っていれば、上流へ送らずに断る。本文は探さない（authd と同じ）。

決まっていないもの（実装の PR に委ねる）:

- ループバックとリンクローカルと私用の範囲（IPv4 と IPv6、IPv4 を IPv6 に写したものを含む）の決め方。クラスタの Pod と Service の範囲を私用の範囲に足す形（範囲が RFC 1918 の外にある環境のため）。
- 関所が、登録したサロゲートの値を知る形（authd から鍵の値でないものだけを受け取るか、登録のうち秘密でない部分を関所にも渡すか）。サロゲートは秘密ではない（ADR-0003）。
- 断ったときと上流に届かなかったときの理由の名前（今の authd の `upstream-unreachable`・`upstream-certificate`・`upstream-failed` と、ループバックとリンクローカルのアドレス・外の名前の私用の範囲のアドレス・サロゲートが載ったものに当たるもの）と、作業環境に返す応答（[関所が返す応答](gate-responses.md) に足す）。
- この部品を、次の版で鍵付きの通信にそのまま使える形（登録の CA で確かめる、authd から受け取った鍵に差し替える）にすること。形は次の版の実装の PR が決める。

## 内側のドメインの一覧

ADR-0008 の Decision「内側のドメインの一覧は、環境が設定で渡す」の形である。

- 関所の設定で、ドメインの並びとして受け取る。一覧のドメインそのものと、その下の名前が「内側の名前」である。名前の比べ方は振り分けと同じ（大文字と小文字を区別せず、末尾の `.` を取る）。
- 役は 2 つ。内側の名前だけが私用の範囲のアドレスにつながる（上の「関所が直に送る」）。内側の名前は、承認の画面と記録で内側と分かるように示す（下の「選択肢の示し方」に足すもの、「記録に足すもの」）。
- 「ドメインの下すべて」の上限は決めない（上の「選択肢の示し方」のとおり、公開の接尾辞の一覧で決める）。
- 読めない・形が誤っているときは、振り分けと同じく起動しないか、読み直しなら前の一覧を使い続ける。どちらでもない形で失えば、空の一覧として扱う（どの名前も私用の範囲につながない）。
- `-dns-search-suffix` とは別の設定にする。渡し方（フラグか、振り分けの設定の欄か）と名前は、実装の PR に委ねる。

## 判定の場所

ADR-0008 の Decision「判定は 1 か所にまとめ、判定器を後から差し込める形にする」の形である。

- 名前解決・TLS の握手（SNI）・開いた要求の 3 つは、どれも同じ判定に「向け直し元・名前・ポート・場面（と、要求なら method・path など）」を渡し、通す・聞く・断る・覚えるの答えと理由と当たった許しを受け取る。
- 判定の順は、振り分けと表の deny、振り分けと表の allow と規則、台帳の許し（操作と宛先）、判定器の場所、残りの既定である。
- 判定器の場所は、この版では何もしない。判定器を入れる版は、ここに「聞くか断るはずだったものを通すか」を決めるものを差し込む。差し込む形（関数の形、記録に残す点数など）は判定器の版が決める。
- 振り分けの名前の判定（今の `routes.Table.Lookup`・`Resolvable`）と、要求の判定（今の `decide.Table`）をこの 1 つにまとめる形は、実装の PR に委ねる。

## 記録に足すもの

[関所の記録](audit.md) に、次を足す。

| 記録 | 足すもの |
|---|---|
| 宛先の許しで答えた名前解決（`dns`） | `verdict` は `allow`、`treatment` は許しの `handling`（`open` か `passthrough`）、`grant` に許しの id、許しで答えたと分かる理由 |
| 宛先の許しで開いた要求（`http`） | `treatment` は `open`、`grant` に宛先の許しの id。書きが ask になったときは、今の ask と同じ |
| 宛先の許しの passthrough（`passthrough`） | `name` に SNI の名前、`grant` に許しの id、中身を見ず読み書きとも通したと分かる理由 |
| 本人が断った名前の一覧から許しを出した（`answer`） | `verdict` は `allow`、`approval` は無い、`grant` に出した許しの id、`name` に名前、理由に選んだ範囲（期限・単位・扱い・読み書き） |
| 宛先の許しの取り消し（`answer`） | 今の取り消しと同じ |
| 運用の係が宛先を先に頼んだ（`agent`） | 今の `agent` と同じ。`name` に最初の名前 |

- 新しい欄を 1 つ足す: 関所が名前を引き直して実際につないだアドレス（IP とポート。仮の名前は `upstreamAddress`、名前は実装の PR が決める）。関所が上流へ直につないだ記録（宛先の許しの `http`・`passthrough`、関所自身の `gate`。次の版からは鍵付きの通信の `http` も）に入れる。引いたアドレスで断ったとき（ループバック・リンクローカル、外の名前の私用の範囲）は、引いたアドレスを並べて入れ、つながなかったことを理由で分かるようにする。authd が送る要求（最初の版の鍵付きの通信）では空である。
- 内側の名前への記録には、内側の名前だと分かる印を入れる。内側の名前が公のアドレスへつないだ記録には、そのことの印を入れる。案は、印を理由の欄の文に足すこと（今の欄で表せ、`treatment` や `verdict` を変えずに済む）。別の欄にするかを含め、形は実装の PR が決める。
- ほかの欄は足さず、今の欄で表す。`treatment` の値に新しいものは足さない。
- 断った名前の覚えは記録ではない。記録の期間で消えない代わりに、上の上限で落ちる。

## 知らせに足すもの

[知らせ](notices.md) に、次を足す。

- 初めて見る組の `destination` は、宛先の許しで開いた要求でも今までどおり取る。許した宛先に初めて通った要求で、1 件知らせる。
- 宛先の許しの passthrough は、新しい組 `granted-passthrough` で、中身を名前とポートにして取る。振り分けの passthrough の組（IP とポート）は、宛先の許しのアドレスが変わるたびに初めてになるためである。
- 本人の答えの知らせに、宛先の許しを出したこと（承認待ちへの答えと、断った名前の一覧から）を足す。中身は、許しの id、承認待ちの id（あれば）、向け直し元、名前、単位・扱い・読み書き、期限。label は今の `answer`（`allowed`）・`grant`・`source` を使い、承認待ちの無いものは `approval` を空にする。
- 1 日のまとめの本人の答えの部分にも、同じものを 1 行ずつ出す。
- 断った名前を覚えたことは知らせない（初めて断った名前の `denied-name` は今までどおり）。

## 指標に足すもの

[指標](metrics.md) に、次を足す。名前と label は実装の PR に委ねる。

- 効いている宛先の許しの数（扱いと読み書きごと、gauge）。
- 覚えている断った名前の数（gauge）と、上限で落とした数（counter）、覚えを書けなかった数（counter）。
- 関所が直に送った宛先の許しの要求・接続を断った数と、上流に届かなかった数（理由ごと）。今の `sentinel_upstream_failures_total` の `reason` に、関所の理由の名前を足す形でよい。authd の指標は変わらない。
- `sentinel_requests_total` の `destination` の label: 許した名前は作業環境が作りうる名前なので、今の「振り分けに無い名前」と同じ扱い（名前を label にしない）にする。

## 環境の側で変わるもの

[向け直しと待ち受け](redirect.md) の規則に、次を足す。

| UID | 足す外向き |
|---|---|
| 関所 | 宛先の許しの通信（開いて見るものと passthrough）のための、ポート 443。ループバックとリンクローカルは落とす |

- authd の UID は変えない。宛先の許しの通信は authd を通らない。ポート 80 はどの UID にも足さない。振り分けの passthrough の範囲に開けているポート 80 も変えない。
- iptables は名前で絞れないので、ポートで開け、どの名前へつなぐかは関所の中で決める。
- クラスタの中と LAN の宛先は、関所の UID の規則では落とさない。外の名前を私用の範囲につながないことは関所の中で確かめ、一覧の名前がどの内側の宛先へ届いてよいかは、環境の側のネットワークの規則（NetworkPolicy など）で決める。
- 内側のドメインの一覧の中身を、関所の設定として渡す。一覧を渡さなければ、宛先の許しはどの名前でも公のアドレスにだけつなぐ。
- 関所の UID の 443 を開けない環境では、宛先の許しは使えない。関所が宛先の許しを出さない（承認の口と作業環境向けの口が断る）設定にする。設定の形は実装の PR に委ねる。

## 実装の PR に委ねるもの

- 断った名前の覚えの上限の数と日数、それを設定にするか。
- 記録の理由の文、関所が直に送ったときの断りと失敗の理由の名前、作業環境に返す応答。
- 実際につないだアドレスの欄の名前。
- 内側のドメインの一覧の渡し方と設定の名前。
- 外の名前に search の接尾辞を付けただけの問い合わせ（接尾辞の下の名前にも許しを出せるので、断った名前の一覧に載る）を、一覧でどう示すか。案は、接尾辞を外した名前も一覧にあるときに畳むこと。
- 内側の名前の印と、内側の名前が公のアドレスへつないだ印の形。
- 関所が登録したサロゲートの値を知る形。
- ループバックとリンクローカルの範囲と、登録できるドメインを決める公開の接尾辞の一覧の持ち方（Go の `golang.org/x/net/publicsuffix` を使うかなど）。
- 判定を 1 か所にまとめるときの型と関数の形。
- 関所の UID の 443 を開けない環境での、宛先の許しの止め方。
