# 関所と authd の間の形

関所は、判定を済ませた要求を、サロゲートを付けたまま authd に渡す（ADR-0003）。ADR-0003 が実装に委ねた「関所と authd の間で要求と断りを渡す形」をここで決める。

## つなぎ方

- authd は Unix socket で待ち受ける。socket は関所と authd の 2 つのコンテナだけが mount する場所に置く。
- authd は、接続の相手の UID を `SO_PEERCRED` で確かめ、`--peer-uid` に与えた UID（関所）以外の接続は、何も読まずに閉じる。閉じたことは authd のログに、相手の UID とともに 1 行残る。
- socket のファイルは、どの UID からも開ける mode にする。相手を分けるのはファイルの mode ではなく UID である。部品の間に共有の秘密は置かない（ADR-0001）。
- 前に動いていた authd が残した socket のファイルは置き換える。socket でないファイルや、まだ誰かが待ち受けている socket は置き換えず、起動を止める。

## socket の上の形

socket の上は HTTP/1.1 である。関所から authd への要求 1 つが、上流への要求 1 つになる。

| 部分 | 中身 |
|---|---|
| 要求の行 | 作業環境の要求の method と、path と query をそのまま |
| `Host` | 関所が判定した上流の名前とポート（`名前:ポート`）。authd はこの名前でつなぐ |
| ほかのヘッダ | 作業環境の要求のまま。サロゲートもそのまま |
| 本文 | 作業環境の要求のまま。溜めずに流す |

authd は、`Host` の名前を自分で引いてつなぎ、上流の証明書をその名前で確かめ、登録した置き場所のサロゲートを本物の鍵に差し替えて、HTTPS で送る（差し替えの決まりは [authd の登録の形式](authd-registration.md)）。

- 上流へは HTTP/1.1 で送る。
- リダイレクトはたどらない。上流の応答をそのまま返す。
- 応答は溜めずに流す。watch・ログの追いかけ・大きな clone・push は、上流が書いた順に届く。
- upgrade（WebSocket・SPDY）は、上流が `101` を返せば、そのまま両方向につなぐ。upgrade を通すかどうかは関所が判定で決める（ADR-0002）。authd は、関所が渡したものを送るだけである。
- 圧縮は authd も関所の側の部品も足さず、外さない。`Accept-Encoding` と応答の本文は作業環境と上流の間のままである。
- `X-Forwarded-For` などの中継のヘッダは足さない。

## 断りと失敗の形

authd が自分で作った応答には、ヘッダ `Authd-Error` が付く。値は理由の名前である。本文は JSON で、理由の名前（`reason`）と記録に残すための短い文（`message`）を持つ。文にサロゲートと鍵の値は入らない。

上流の応答に同じ名前のヘッダがあれば、authd が取り除く。`Authd-Error` があるのは authd の言葉だけである。

| 理由 | 分け | 状態 | 起きるとき |
|---|---|---|---|
| `upstream-not-registered` | 断り | 403 | 名前かポートが登録に無い |
| `surrogate-mismatch` | 断り | 403 | サロゲートと上流の名前の組、または置き場所が登録と合わない。登録していない置き場所にサロゲートが残っている |
| `credential-unavailable` | 断り | 403 | 本物の鍵のファイルが読めない |
| `bad-request` | 断り | 400 | `Host` が名前とポートの形でない。関所の誤りである |
| `upstream-unreachable` | 失敗 | 502 | 名前が引けない、つなげない |
| `upstream-certificate` | 失敗 | 502 | 上流の証明書が確かめられない |
| `upstream-failed` | 失敗 | 502 | そのほかの理由で上流とのやりとりが壊れた |

「断り」は authd が自分の確かめで送らなかったもの（ADR-0003 の「authd も自分で確かめ」）、「失敗」は確かめを通ったが上流から応答が得られなかったものである。どちらも上流の応答ではない。記録は関所が書き、authd は記録を書かない（ADR-0006）。

失敗の文は、失敗の種類だけから作る。上流とのやりとりの誤りの文には、鍵を差し替えたあとの URL が入りうるので、そのまま返さない。

## 関所の側の部品

関所の側は、パッケージ `internal/authdclient` の `Transport` を `http.RoundTripper` として使う。

- 作るときに、authd の socket のパスを与える。socket へは最初に使うときにつなぐ。
- 渡す要求の URL は `https://名前:ポート/…` の形にする。名前とポートは関所が判定したものである。ポートを省けば 443 として送る。`https` 以外の URL と、URL と違う名前の `Host` を持つ要求は、authd に渡さずに誤りを返す。
- authd が断った、または上流に届かなかったときは、応答ではなく `authdclient.Error` を誤りとして返す。誤りは理由（`Reason`）と文（`Message`）を持ち、断りか失敗かを `Refused` で見分けられる。関所は `errors.As` で取り出して記録に残す。
- authd につなげなかったときは、`authdclient.Error` ではない誤りを返す。これは authd が止まっているか、socket が無いときで、関所は通さない側に倒す（ADR-0001 の「止まったら閉じる」）。
- 上流が返した 403 などの応答は、誤りではなく応答として返す。
- このパッケージは鍵を読まず、鍵を読むパッケージ `internal/authd` に依存しない。関所の binary に鍵を読むコードが入らないことは、テストで確かめている。
