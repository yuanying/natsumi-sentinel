# 知らせ

関所（`sentinel`）が、いつもと違うことを本人に知らせる形を決める。何を知らせるか、「初めて見る」の覚えを記録と別に持つこと、natsumi と運用の係に頼らない道で届けることは ADR-0006 の Decision「いつもと違うことを知らせる」が決め、組の細かな取り方・まとめの形・届ける道の作りをこの文書（と実装）に委ねている。

## 何を知らせるか

| 知らせ | いつ |
|---|---|
| 初めて見る組（`first-seen`） | 組を初めて見たとき、1 件ずつ |
| 1 日のまとめ（`daily-summary`） | 1 日 1 回、決めた時刻に |

本人の答え（承認待ちへの答えと許しの取り消し）を受けたことの知らせは、答えを受ける口ができる判定の版で足す。

## 初めて見る組

関所は、書き終えた記録を 1 件ずつ見て、次の組を取り出す。

| 組（`pair`） | 取り出す記録 | 組の中身（`key`） |
|---|---|---|
| `destination` | 開く宛先へ通した要求（`kind` が `http`、`verdict` が `allow`） | 宛先の名前 |
| `write` | 開く宛先へ通した書きの要求（GET・HEAD・OPTIONS・TRACE 以外） | 名前・method・path を空白でつないだもの |
| `passthrough` | passthrough でつないだ接続 | 元の宛先の IP とポート |
| `denied-name` | 名前解決で断った問い合わせ（`kind` が `dns`、`verdict` が `deny`） | 問い合わせた名前 |

- 書きの組は、記録に操作と対象の欄がまだ無いので、名前・method・path で取る。query は組に入れない。path に番号の入る API（issue の番号など）では、番号ごとに別の組になる。操作と対象の欄が記録に入ったら、そちらで取るように改める。
- 断った要求と接続、振り分けの読み直し、関所自身の要求は組にしない。断ったものは 1 日のまとめに出る。
- 名前解決の問い合わせは、通した名前を組にしない。通した名前は、その名前への要求が `destination` の組になる。

### 覚え

- 見た組は、関所の SQLite のファイルの表 `seen` に、初めて見た記録の時刻と番号とともに残す（[関所の記録](audit.md) の「置き場所」）。
- この表は記録と別に持ち、古い記録を消すときにも消さない。記録の期間が過ぎても、一度見た組は「初めて」にならない。
- 表が空のうちは、何もかもが初めてなので知らせが多い（ADR-0006 の Consequences）。

## 1 日のまとめ

- 関所は、`-summary-at`（`HH:MM`、既定 `00:00`）の時刻に、`-summary-timezone`（IANA の名前、既定 `UTC`）で、まとめを作る。まとめが扱うのは、前の日の同じ時刻から、その時刻までの記録である。
- その時刻に関所が動いていなければ、その日のまとめは後から作らない。

まとめには、次の 3 つを書く。

| 部分 | 中身 |
|---|---|
| 書きの件数 | 開く宛先へ通した書きの要求の件数を、宛先と method ごとに、多い順に |
| 新しく現れた組 | その期間に初めて見た組（上の表の組と中身）を、古い順に |
| 通さなかったもの | `verdict` が `allow` でない記録を、扱い・種類・宛先・method・path・理由が同じものごとにまとめ、件数の多い順に |

- 各部分は 30 行までで、残りは件数だけを書く。
- 通さなかったものには、振り分けの読み直しと、関所自身の要求は入れない。ask は、判定の版で `verdict` に入ったときから、ここに並ぶ。

## 届け先

### Alertmanager に送る

- `-alertmanager-url` に Alertmanager の基の URL（`https://名前[:ポート][/path]`）を与えると、関所は知らせを、その下の `/api/v2/alerts` へ、Alertmanager の v2 の API の alert として POST する。Alertmanager から先（Slack の専用のチャンネルへの route）は、環境のリポジトリが持つ。
- 送るのは、作業環境の要求と同じ authd への送り口である。関所は上流へ直に出ない（ADR-0002）。authd の登録に Alertmanager の名前が無ければ、authd が断り、知らせは送れない。
- 送るたびに、関所自身の要求として記録に残す（`kind` が `gate`）。記録が書けなければ送らない。
- URL には、ユーザー・query・fragment を書けない。`https` でなければ使わない。

### alert の形

| 部分 | 中身 |
|---|---|
| label `alertname` | `SentinelFirstSeen`（初めて見る組）か `SentinelDailySummary`（まとめ） |
| label `severity` | いつも `info` |
| label `pair`・`key`・`source` | 初めて見る組の、組・中身・向け直し元の待ち受けの名前 |
| label `day` | まとめの期間の始まりの日（`YYYY-MM-DD`、`-summary-timezone` で） |
| ほかの label | `-alert-label` に `名前=値` で与えたもの（繰り返せる）。どのインスタンスの関所かを示すのに使う |
| annotation `summary` | 1 行の要約 |
| annotation `description` | 詳しい文。まとめは複数の行になる |
| `startsAt` | 知らせることが起きた時刻（組を初めて見た記録の時刻、まとめの期間の終わり） |
| `endsAt` | 送った時刻の 1 時間後 |

- 知らせには解消という状態が無い。`endsAt` は送った時刻から決めるので、遅れて送った知らせも、1 度は届く。
- 初めて見る組の label の値と `summary` は 256 バイト、`description` は 2048 バイト、まとめの 1 行は 256 バイトで切り、切ったことを `…` で示す。path は作業環境が決めるもので、長くなりうるためである。

### 送れなかったとき

- 送れなかった知らせは関所のメモリの中で待ち、1 分ごとと、次の知らせができたときに送り直す。1 度に 100 件までをまとめて送る。
- 待てるのは `-notice-queue`（既定 1000）件までで、超えたら古いものから捨て、`sentinel_notices_dropped_total` に数える。
- 止まるときに、待っているものを 5 秒だけもう 1 度送ってみる。それでも送れなかったもの、関所が止まったときに待っていたものは失われる。初めて見た組は覚えに残るので、その日のまとめの「新しく現れた組」には出る。
- 送り損ないは指標に出る（[指標](metrics.md)）。

### Alertmanager を使わないとき

- `-alertmanager-url` を与えなければ、知らせは関所の標準エラーのログに出すだけにする。関所はそのまま動く。
- 知らせの設定（`-alertmanager-url`・`-alert-label`・`-summary-at`・`-summary-timezone`）が使えないときも、関所は起動する。使えないことを標準エラーに出し、URL が使えなければログに出すだけに、時刻や時間帯が使えなければ既定の値に倒す。知らせの設定は関所を止める理由にしない。`sentinel_notice_sender_configured` が 0 なら、知らせは Alertmanager へ届いていない。
- どちらの場合も、すべての知らせは送るかどうかによらず標準エラーに 1 行ずつ出る。

## 知らせに入れないもの

- 鍵・token・サロゲートの値、要求のヘッダ、要求と応答の本文、query は入れない。入るのは、何をしたか（method と path）、どこへ（名前・IP とポート）、何件か、どう決めたか（理由）までである。
- path と、断った名前解決の名前は、作業環境が決めた値である。そこに書かれたものは、そのまま知らせに出る。

## 環境の側で要るもの

関所のリポジトリの外で、次のものを用意する。

| もの | 中身 |
|---|---|
| Alertmanager の HTTPS の名前 | authd は HTTPS でしか送らず、上流の証明書をその名前で確かめる。クラスタの中の Alertmanager を、TLS を終端する名前（Service の前の TLS の終端、Ingress など）で届くようにする |
| authd の登録 | `upstreams` に、その名前とポートを足す。証明書が自前の CA のものなら `ca_file` を書く |
| 鍵 | Alertmanager の v2 の API に認証が無ければ、鍵の登録は要らない。前に認証を置くなら、サロゲートを置く口が関所の側に要る（この版には無い） |
| Alertmanager の route | `alertname` が `SentinelFirstSeen`・`SentinelDailySummary` のものを、Slack の専用のチャンネルへ流す。1 件ずつ届くよう `group_by` に `pair` と `key`（まとめは `day`）を入れ、解消の知らせ（`send_resolved`）は切る |
| 関所のフラグ | `-alertmanager-url`、インスタンスを示す `-alert-label`、本人の時間帯の `-summary-at` と `-summary-timezone` |
| 指標の scrape と規則 | 関所と authd の `-metrics-listen` を scrape し、[指標](metrics.md) の「知らせの規則に使うもの」の規則を置く |

関所自身の要求は、振り分け（[振り分けの形式](routes.md)）で決めない。Alertmanager の名前を振り分けに書く必要は無い。
